# ストア申告の回答案（App Store Connect／Play Console）

作成：2026-10-09。前提：アプリ版に AdMob・Firebase（Analytics、Crashlytics、Remote Config）を入れる。ログインなし、サーバーなし、アプリ内課金なし、18歳以上向け。
**最終的な回答の責任は開発者にあります。** 提出する直前に、Google の公式ガイド（AdMob と Firebase の「データ開示」ページ）で、入れた SDK の版の項目と照らし合わせてください。法的助言ではありません。

---

## 1. Google Play「データ セーフティ」

| 質問 | 回答案 |
|---|---|
| 必須のユーザーデータを収集または共有しますか | はい（SDK が集めるため） |
| 送信中のデータはすべて暗号化されていますか | はい |
| ユーザーがデータの削除をリクエストできますか | 「いいえ」でよい（アカウントがなく、開発者がデータを持たない）。ゲーム内の「セーブを消す」は端末内のデータなので申告対象外。説明欄があれば書く |
| アカウント作成 | なし（→ 削除用URLは不要） |

| データの種類 | 収集 | 共有 | 任意か | 目的 | どの SDK |
|---|---|---|---|---|---|
| 位置情報 › おおよその位置 | はい | はい | 必須 | 広告、分析、不正防止 | AdMob（IPから推定） |
| アプリのアクティビティ › アプリの操作 | はい | はい | 必須 | 広告、分析 | AdMob、Analytics |
| アプリの情報とパフォーマンス › クラッシュログ | はい | いいえ | 必須 | 分析、アプリの機能 | Crashlytics |
| アプリの情報とパフォーマンス › 診断 | はい | はい | 必須 | 広告、分析、不正防止 | AdMob、Crashlytics |
| デバイスやその他の ID | はい | はい | 必須 | 広告、分析、不正防止 | AdMob（広告ID、App Set ID）、Firebase（インスタンスID） |

- 「共有」は第三者への受け渡し。Firebase のように**開発者の代わりに処理するサービス（サービスプロバイダ）への送信は共有に当たらない**、と Google は説明しているため、Crashlytics だけのデータは「共有：いいえ」。AdMob は Google 自身の目的にも使うため「共有：はい」。
- その他の Play Console の項目：
  - 広告：**含む**
  - アプリのアクセス権：制限なし（ログイン不要）
  - 対象年齢：**18歳以上のみ**。「ファミリー向け」には参加しない
  - コンテンツのレーティング（IARC）：下の 3 を参照
  - ニュースアプリ／金融機能／健康／政府：該当なし
  - **実際のお金のギャンブル：なし**。模擬ギャンブル（ソーシャルカジノ）として申告

## 2. Apple「App のプライバシー」

| データの種類 | 用途 | ユーザーに紐づくか | トラッキングに使うか |
|---|---|---|---|
| 識別子 › デバイスID | 他社の広告、アナリティクス | いいえ（アカウントがないため）※ | **はい**（ATT で許可された場合に AdMob が使う） |
| 使用状況データ › 製品の操作 | アナリティクス、他社の広告 | いいえ | いいえ |
| 使用状況データ › 広告データ | 他社の広告 | いいえ | はい |
| 診断 › クラッシュデータ | アプリの機能 | いいえ | いいえ |
| 診断 › パフォーマンスデータ | アプリの機能、他社の広告 | いいえ | いいえ |
| 位置情報 › おおよその場所 | 他社の広告 | いいえ | いいえ |

※ Google のガイドの記載を優先する。「トラッキングに使う」を「はい」にするなら、ATT のダイアログと `NSUserTrackingUsageDescription` が必須。
- `NSUserTrackingUsageDescription` の文面案：「あなたの興味に合った広告を表示するために使います。許可しなくてもゲームはすべて遊べます。」／英語：「Used to show ads that match your interests. You can play the whole game without allowing this.」
- プライバシーマニフェスト：Preferences（UserDefaults）を使う理由 `CA92.1`（アプリ自身のデータの保存）。Google の SDK は各自のマニフェストを同梱している。

## 3. 年齢区分

### Apple（2025年からの新しい質問票）
| 項目 | 回答案 | 理由 |
|---|---|---|
| 模擬ギャンブル | **頻繁** | ポーカーが遊びの中心 → 18+ の見込み |
| アルコール・たばこ・薬物の使用や言及 | まれ／軽度 | 舞台がバーで、飲み物のセリフがある |
| 成人向け／示唆的なテーマ | まれ／軽度 | 裏切りなどの物語 |
| 暴力（アニメ・リアル） | なし | |
| 下品なユーモア・汚い言葉 | なし〜まれ | 「感じの悪い客」のセリフを確認して決める |
| 医療・ホラー・性的表現 | なし | |
| コンテスト | なし | |
| 制限のない Web アクセス | なし | ポリシー等のリンクは外部ブラウザで開くだけ |
| ユーザー生成コンテンツ・メッセージ | なし | 呼び名は端末内だけ |
| 広告 | あり | |
| 保護者による制限・年齢確認の仕組み | なし | |

### Google Play（IARC）
- 「ギャンブルの要素：模擬ギャンブルを含む（実際のお金・景品なし）」「ユーザー同士のやり取り：なし」「位置情報の共有：なし」「デジタル商品の購入：なし」「アルコールへの言及：あり」で回答し、**出た区分をそのまま使う**（国ごとに区分が付く）。

## 4. その他の申告

| 項目 | 回答案 |
|---|---|
| 暗号化（輸出規制、Apple） | `ITSAppUsesNonExemptEncryption = NO`（OS 標準の HTTPS しか使わない） |
| コンテンツの権利（Apple） | 第三者の素材を含む（フォント、OFL）。権利は確認済み |
| EU のトレーダー（DSA） | **トレーダーとして申告**（広告で収益を得るため）。住所・電話・メールがストアに表示される。自宅を出したくなければバーチャルオフィスを用意（[モバイルアプリ化調査.md](../mobile/モバイルアプリ化調査.md) 6章） |
| Google Play の連絡先の公開 | 収益化している個人アカウントは住所が公開される場合がある（同上） |

## 5. 新しく調べて分かったこと：米国の州法による年齢確認（2026年）

- 米国の一部の州で「アプリストア年齢確認法」が始まっている。**テキサス州は2026年6月から実施**（裁判所の判断を受けて Apple が開始）。ユタ州（開発者の義務 2026年5月から、執行 2026年12月末から）、ルイジアナ州（2026年7月から）、アラバマ州・カリフォルニア州（2027年1月から）。
- Apple は「Declared Age Range API」、Google は「Play Age Signals API」で、ストアが確認した年齢の区分（18歳以上かどうかなど）をアプリに渡す仕組みを用意している。年齢区分を変えると「大きな変更」として保護者の同意が要る扱いになる（テキサス）。
- このゲームは 18+ で出す予定なので、未成年はストアの段階で入手しにくい。ただし**州法は対象年齢に関係なく全アプリにかかる**、という解説もある（推測を含む。弁護士の確認ではない）。
- **おすすめの対応（アプリ化のとき）**：アプリ版の「薄い部分」で両方の API を読み、18歳未満と分かった場合は「このゲームは18歳以上向けです」と表示して広告をパーソナライズしない設定（AdMob の未成年向けタグ）にする。年齢の情報は保存せず、広告や計測にも使わない（Google の規則）。米国配信を始める直前に、そのときの Apple・Google の案内を確認する。

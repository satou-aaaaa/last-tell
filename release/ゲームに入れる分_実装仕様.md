# 公開に向けてゲームに入れる分（実装仕様）

作成：2026-10-09（「公開に必要なもの」スレッド）。対象：`story/shisho.html`。担当：ゲーム本体のスレッド。
前提：Web版（PWA、テストサイト）とストア版（Capacitor）を**両方同時に**進める（satouさん決定 2026-10-09）。ドメインは後で決める。
守ること：第1〜3章の勝率は変えない。ジンの本物のテルには触れない。チップを現金で売らない。タイトルなどに「夜」を使わない。会話にお金の話を入れない。

優先度：**A＝次の版で入れたい**、B＝ストア提出までに、C＝アプリ化（Capacitor）の段階で。

---

## A-1. 横向きで「勝負開始」が押せない（不具合）

- 再現：フリー対戦（4人）を 844×390 の横向きで開く → 対戦相手の紹介（`#vs`）の「勝負開始」ボタンが y=411〜455 で画面の外。`#vs` は `position:fixed` で `overflow` がないため、スクロールもできない。v51・v53 とも同じ。
- 直し方（テストサイトで一時的に入れて確認済み）：
  ```css
  .vs{overflow-y:auto;place-items:safe center}
  ```
- 本体に入ったら、テストサイトの一時修正（`tools/build_index.py` の `pwa-tmpfix`）を消す。

## A-2. PWA の行を本体に入れる

テストサイトでは `tools/build_index.py` が公開のたびに頭に足しているが、本体に入れておけば Artifact・テストサイト・アプリで同じファイルを使える。

ファイルの先頭（今の `<title>` の前）に：
```html
<!doctype html>
<html lang="ja">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<meta name="theme-color" content="#0d0e13">
<link rel="manifest" href="manifest.webmanifest">
<link rel="icon" type="image/png" sizes="32x32" href="icons/favicon-32.png">
<link rel="apple-touch-icon" href="icons/apple-touch-icon.png">
<meta name="mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="black">
<meta name="apple-mobile-web-app-title" content="LAST TELL">
```
ファイルの最後に：
```html
<script>
if('serviceWorker' in navigator && (location.protocol==='https:'||location.hostname==='localhost')){
  addEventListener('load',()=>navigator.serviceWorker.register('sw.js').catch(()=>{}));
}
</script>
```
- Artifact では manifest やアイコンが見つからないだけで、動作には影響しない（登録は失敗しても何もしない）。
- `<!doctype html>` がないと古い表示モード（quirks）になる。テストサイトは今まで doctype と viewport がなく、スマホで PC 幅（980px）の縮小表示になっていた。PWA 化で直した。

## A-3. 「ホーム画面に追加」の案内

- 下の B-1「その他」画面に「ホーム画面に追加」の行を置く。
- Android／PC の Chrome：`beforeinstallprompt` を受け取って保存しておき、ボタンで `prompt()`。受け取っていなければ「ブラウザのメニューから『アプリをインストール』を選んでください」と出す。
- iPhone／iPad（`navigator.standalone` が false の Safari）：「共有ボタン →『ホーム画面に追加』」の説明を出す。
- すでにホーム画面から起動している（`matchMedia('(display-mode: standalone)').matches` か `navigator.standalone`）なら行ごと隠す。アプリ版（Capacitor）でも隠す。

## A-4. 新しい版が出たときの表示

Service Worker はページ本体をネット優先で読むので、ネットにつながっていれば次の起動で新しい版になる。追加の処理は不要。将来「キャッシュ優先」に変えるときに、「新しい版があります → 再読み込み」の表示を入れる（今は不要）。

## B-1. タイトルに「その他」画面

今は設定が卓の中（`#setPanel`）にしかなく、ポリシーやクレジットを置く場所がない。タイトルのボタン列に「その他」を1つ足し、次の画面（`section#more`）を開く。

| 区分 | 行 | 動き |
|---|---|---|
| 設定 | 設定 | 今の `#setPanel` をタイトルからも開けるようにする |
| | ホーム画面に追加 | A-3 |
| データ | 引き継ぎコードを出す | B-2 |
| | 引き継ぎコードを入れる | B-2 |
| | セーブを消す | B-3 |
| 情報 | プライバシーポリシー | `LINKS.privacy` を新しいタブで開く |
| | 利用規約 | `LINKS.terms` |
| | お問い合わせ | `LINKS.support`（メール作成ではなくページへ。メールアドレスはページ側に書く） |
| | クレジットとライセンス | B-4 |
| | プライバシー設定 | アプリ版で同意のやり直しが必要な地域だけ表示（C-2）。Web版では隠す |
| 下に小さく | 版 `LAST TELL v0.53` ／「チップは点数です。現金や景品とは交換できません。」 | |

- リンク先はファイル先頭の1か所にまとめる：
  ```js
  const APP_VERSION='0.53.0';
  const LINKS={privacy:'privacy.html',terms:'terms.html',support:'support.html'}; // ドメインが決まったら差し替え
  ```
  いまは相対パスにしておけば、テストサイトの同じ場所に置いたページが開く（ページは `release/site/` にある。公開はテストサイトのスレッドが行う）。
- 英語表示のときは `privacy-en.html` などに切り替える。
- 新しい文字はすべて `EN_DICT` に英語を足す。

## B-2. 引き継ぎコード

保存先は今 19 個（`shisho-progress`、`-settings`、`-notes`、`-manners`、`-regular`、`-quiz`、`-titles`、`-stars`、`-advice`、`-review`、`-ura`、`-run`、`-read`、`-story`、`-guide`、`-daily`、`-rumor`、`-leaks`、`-talk`）。名前は変えない（変えると今のセーブが読めなくなる）。

- 一覧を1か所に：`const SAVE_KEYS=[...]`。今後キーを足すときはここにも足す。
- **出す**：
  1. `{"app":"lasttell","fmt":1,"ver":APP_VERSION,"data":{キー: 中身のオブジェクト, ...}}` を作る（空のキーは入れない）
  2. `CompressionStream('deflate-raw')` で圧縮し、Base64URL にする（使えない古いブラウザでは圧縮なしで Base64URL）
  3. `LT1` ＋（圧縮ありなら `z`、なしなら `p`）＋ `-` ＋本体 ＋ `-` ＋確認用4文字（本体の CRC32 を36進数にした下4桁）
  4. 画面にコードと「コピー」ボタン。「機種変更やアプリ版への引き継ぎに使えます。他の人には教えないでください」の注意
- **入れる**：
  1. 貼り付け欄＋「読み込む」。前後の空白・改行は取り除く
  2. 形が違う／確認用4文字が合わない → 「コードが正しくありません。コピーし直してください」
  3. 合えば「第◯章までクリア、称号◯個」の要約を出し、「今のセーブを上書きします」の確認
  4. `SAVE_KEYS` にあるキーだけを書き込み（ないキーは消す）、ページを読み直す
  5. 中の各オブジェクトの `v` が今の版より新しければ「新しい版のゲームで作られたコードです。ゲームを更新してください」で止める
- 改ざん防止は不要（1人用でランキングなし）。確認用4文字は打ち間違いの検出のため。
- テスト：出す→セーブを消す→入れる で元に戻ること。日本語の入ったメモ（`shisho-notes`）・呼び名も戻ること。英語表示でも同じ。

## B-2b. セーブをファイルに書き出す／読み込む

引き継ぎコードと同じ中身を、ファイルでもやり取りできるようにする（コードのコピーが苦手な人向け、バックアップ用）。

- 「その他 → データ」に2行足す：「セーブをファイルに保存」「ファイルから読み込む」。
- **保存**：B-2 の1で作る JSON（圧縮しない、読める形）を `LAST_TELL_save_YYYYMMDD.json` として保存。`Blob` ＋ `<a download>` で保存させる。iPhone の Safari・ホーム画面版では「ファイル」アプリに保存される。`navigator.share` が使え、ファイル共有に対応していれば（`navigator.canShare({files})`）共有シートを優先してもよい。
- **読み込み**：`<input type="file" accept=".json,application/json">` で選ばせ、中身を B-2 の「入れる」の3〜5と同じ確認・書き込みに回す。`app` が `lasttell` でなければ「LAST TELL のセーブファイルではありません」。
- アプリ版（Capacitor）では、保存は `@capacitor/filesystem` ＋ `@capacitor/share` に差し替える（`LT_PLATFORM.saveFile(name, text)` を呼び口に足し、Web版の既定は上の Blob 保存）。

## B-2c. ブラウザに消されにくくする

- 起動時に1回 `navigator.storage?.persist?.()` を呼ぶ（結果は使わなくてよい）。Chrome はホーム画面に追加した場合などに許可し、ブラウザの容量が足りないときでもセーブを消しにくくなる。Safari は対応状況が限られるが、呼んでも害はない。
- 「その他」画面の「データ」の下に、Web版のときだけ小さく「ブラウザのデータを消すとセーブも消えます。ときどきファイルに保存しておくと安心です」と出す。

## B-3. セーブを消す

- 「セーブを消す」→ 確認画面「すべての進み具合・設定・メモが消えます。元に戻せません。先に引き継ぎコードを出しておくこともできます」→「消す」を押すと `SAVE_KEYS` をすべて削除してタイトルへ。
- 間違い防止に、確認画面の「消す」は1秒後から押せるようにする（または2段階）。
- EU の「削除の権利」への答えにもなる（開発者のサーバーにはデータがないので、端末の中を消せれば足りる）。

## B-4. クレジットとライセンス画面

文面は [クレジットとライセンス.md](クレジットとライセンス.md)。ゲーム内では短い一覧を出し、フォントのライセンス全文は `licenses/` の文字ファイルへのリンクにする（テストサイトに一緒に置く）。

## B-5. 初回だけの注意

最初の起動で1回だけ、タイトルの上に小さく出す（閉じたら `shisho-settings` に `seenNotice:true`）：
> このゲームは、ポーカーを題材にした1人用のゲームです。チップは点数で、現金や景品とは交換できません。実際のお金を賭けることを勧めるものではありません。

年齢を入力させる画面は作らない（ストアの年齢区分で扱う。生年月日を集めるとポリシーの範囲が広がる）。

## C. アプリ化（Capacitor）の段階で入れるもの

アプリ側の実装は [app/](app/README.md) に作成済み（`src/platform.js`）。本体には「呼び口」だけを先に用意し、Web版では何もしない形にしておくと、アプリ化のときに本体を触らずに済む。

```js
// Web版の既定。アプリ版はこれを上書きする
window.LT_PLATFORM=window.LT_PLATFORM||{
  name:'web',
  openUrl:u=>window.open(u,'_blank','noopener'),
  track:(event,params)=>{},          // 計測（C-3）
  reportError:(err)=>{},             // クラッシュ検知（C-4）
  privacyOptionsRequired:()=>false,  // 「プライバシー設定」の行を出すか（C-2）
  showPrivacyOptions:()=>{},
  saveFile:null,                     // アプリ版はファイル保存を差し替える（B-2b）
  adBreak:async()=>false,            // 広告（C-7）。Web版は何もしない
  showRewarded:async()=>false,
  canShowRewarded:()=>false,
};
```

| # | 内容 | 本体でやること |
|---|---|---|
| C-1 | Android の戻るボタン | `window.LT_back()` を用意：開いている窓（`#setPanel`、`#help`、`#quiz` など）を閉じる → 卓なら「やめる」確認 → 章選択ならタイトル → タイトルなら false を返す（アプリ側が終了確認を出す） |
| C-2 | 同意のやり直し | 「その他」の「プライバシー設定」行を `LT_PLATFORM.privacyOptionsRequired()` が true のときだけ出し、押したら `showPrivacyOptions()` |
| C-3 | 計測 | 次の場所で `LT_PLATFORM.track()` を呼ぶ：`chapter_start{ch}`、`chapter_clear{ch}`、`game_over{ch}`、`free_start{size}`、`daily_play`、`transfer_export`、`transfer_import`。年齢・名前・呼び名などは送らない |
| C-4 | エラーの報告 | `window.onerror` と `unhandledrejection` で `LT_PLATFORM.reportError()` |
| C-5 | 広告中の音 | `const Sound` の定義のあとに `window.Sound=Sound;` を1行足す（今はトップレベルの const なので外から見えない）。アプリ側が広告の前後で `Sound.pause()`／`Sound.resume()` を呼ぶ |
| C-7 | 広告を出す場所 | 章のクリア／負けの画面、フリー対戦の終了で `LT_PLATFORM.adBreak?.('chapter_end')` などを呼ぶ（Web版の既定は何もしない）。フリー対戦でチップが尽きたとき、`LT_PLATFORM.canShowRewarded?.()` が true なら「動画を見て続ける」ボタンを出し、`await LT_PLATFORM.showRewarded('refill')` が true なら持ち点を戻す。第1章の途中には出さない |
| C-6 | フォント | Google Fonts の読み込みを、同じ場所に置いたフォントファイル（`fonts/`）に切り替えられるようにする（`<link>` を1行差し替えるだけで済む形）。Web版は Service Worker がフォントを保存するので今のままでも動く |

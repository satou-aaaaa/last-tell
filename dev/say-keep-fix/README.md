# セリフが途中で切れる不具合の修正（2026-10-10 satou 報告）

satouさんの報告：「セリフのやりとりが途中で切れたりしている」「ポーカーのアクションが入ると中断されるように見える」

## 原因（v63 で再現）
1. 吹き出しは1人1つだけ。話している最中にその人が打つと、打つときのひとこと（「ついていく！」など）で前のセリフが読む前に上書きされていた（フリー6人で8件。掛け合いの行が 0.4〜1.5秒で消えたものもあった）。
2. 自分が先に打つ席だと、ハンドの頭の掛け合いの分の待ち時間（S.hold）が自分の番で消えてしまい、自分が打つとすぐに CPU が打ち始めて掛け合いに割り込んでいた。
3. 掛け合いの途中で「次のハンドへ」を押すと、残りの行が消えていた。

## 直し方：新しいファイル src/js/35_say_keep.js（lane.py で書き戻し済み）
- 1つ前のセリフを読み終わるまでは、同じ人の次のセリフを出さない（文字数から 1.1〜2.8秒）。掛け合いの行を待たせている間に打つときのひとことが来たら、掛け合いの行を残す。
- 自分が打ったときに掛け合いが残っていれば、次の CPU はその分だけ待つ（act:before で S.hold を足す）。
- 掛け合いの途中で次のハンドを配ったら、残りを次のハンドの頭で続ける（S.bSilent。問いかけの組は今までどおり）。
- 合図は LT.on（render:before / render / act:before / startHand:before）。本体の関数は包み直していない。ただし 25_cpu.js の bSay は、同じ中身で進み（S.sayKeep）を数えるものに置き換えている（本線が 25_cpu.js に取り込んでもよい）。

## order.json（本線へ）
- `js/35_say_keep.js` を `js/34_fold_muck.js` の後、`js/35_hooks_wire.js` の前に。
- **00b_hooks.js と 35_hooks_wire.js が order.json に入っていることが前提**（LT.on を使うため）。

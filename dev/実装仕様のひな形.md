# 実装仕様のひな形（2026-10-10〜）

提案が決まったあと、`research/<名前>_実装仕様.md` をこの形で書きます。ゲーム担当が読み直して書き直す手間と、訳し漏れを減らすためのものです。

## 提案の作り方（決まる前）
- 作るのは「案の比較＋見本（Artifact）」まで。実装仕様は、satouさんが選んだ案の分だけ、選ばれた後に書く。
- 提案の最後に「クリエイター目線の3行」を付ける：どの柱に効くか（テルを読む／師弟の物語／ライブの空気）、最初の5分への影響、1.0 に入れるべきか公開後か（2026-10-10 satou 決定）。
- 動画（mp4）は、動きが大事な提案（演出・カメラ・アニメーション）だけ。文章や仕組みの提案には作らない。

## ひな形

```markdown
# <名前> 実装仕様

## 1. 何が変わるか（遊ぶ人から見て）
2〜5行。

## 2. 触る場所
- ファイル：（切り替え後）src/js/25_cpu.js など。切り替え前は shisho.html の見出し名（例「/* ---------- CPU：勝率を見積もり」）
- 新しく足すファイルがあれば名前
- 他の作業と重なる場所（例：CPU は「プロ目線の修正」と同じ）

## 3. 保存キー
- 新しいキー名と中身の形（例 shisho-banter {v:1, seen:[…]}）。無ければ「なし」
- その他画面の「セーブを消す」「引き継ぎコード」に入れるか

## 4. データ（そのまま入れられる形）
台詞・名前・数値は、別ファイル research/<名前>_データ.js に置く。日本語と英語を並べる。
    const XXX=[ {ja:'……', en:'……', who:'ゲン'}, … ];
英語が無い行は入れない。

## 5. 守ること
- 第1〜3章の難しさを変えない／第7章のジンの本物のテルに触れない
- 「夜」を使わない（「あの日」）／セリフにお金の話を入れない
- そのほか、この仕様だけの決まり

## 6. 「できた」の条件（自動検証に足せる形）
1行ずつ、機械で白黒がつく書き方にする。
- 例：第4章以降、強いキャラ（rank 4 以上）がプリフロップでリンプしない（1000ハンドで0回）
- 例：掛け合いは第7章で1回も出ない
- 例：新しい日本語の文字列は全部 EN_DICT にある
目で見る確認が要るものは「目で見る：」を頭に付けて分ける。
```

## レーンの進め方
**作業場所のファイルを src/ に丸ごとコピーして戻さないこと。** 2026-10-10 の最初の回で、古い写しを上書きして本線の v61 の修正（「完」の位置、ケンジのセリフ）を消してしまいました。書き戻しは必ず `lane.py` を使います。

1. 作業場所を作る：`python3 /mnt/project-files/dev/tools/lane.py checkout <自分のscratch>/lane`
   （src/ の写しと、その時点の控え `.base` ができる）
2. 担当ファイルだけを変える。新しいファイルは写しの order.json に足す。
3. 組み立てて確かめる：`python3 /mnt/project-files/dev/tools/build.py <scratch>/lane/src <scratch>/test.html`、qa/ の自動検証、スマホ縦・横・PC の画面確認。
4. 途中で `lane.py status <scratch>/lane` を見ると、自分が変えたファイルと、その間に src/ 側で変わったファイルが分かる。
5. 書き戻す：`python3 /mnt/project-files/dev/tools/lane.py writeback <scratch>/lane js/02_chapters.js js/12_story_bits.js …`
   - src/ がその間に変わっていなければ、そのまま書く。
   - 変わっていたら、自分の変更だけを今の src/ に当てる（3方向マージ）。
   - 同じ行がぶつかったら何も書かずに止まる。今の src/ を読んで当て直す。
6. order.json に足す行を本線へ伝える（まとめ役経由）。本線が組み立て → 検証 → 公開。

## 本線の進め方
- 版の正式な検査は GitHub で回す（2026-10-14）：`publish-v<版>` のプルリクエストが自動で長い版になる。手元で `run_all.sh --official` は回さない。CI が終わったら `sh qa/ci_result.sh <番号> --save v<版>` で `qa/reports/v<版>/` に写す。クリエイター目線・UI/UX・交代レビューは `ci_result.sh v<版> --shots` で読む。基準の書き直しは、その版の `baseline_候補.json` を `qa/baseline.json` に写す（satou さんの OK のあと）。
- 変更は src/ のファイルを直接直す。置き換えスクリプトの形のまま当てたいときは `python3 dev/tools/apply_patch.py src patchNN.py`（組み立て → パッチ → 分け直し → 1文字も違わないか確認）。
  - 注意：apply_patch は見出しで分け直すので、レーンが足した別ファイルがある間は使わない（中身が前のファイルに混ざる）。
- 公開する版ごとに `snapshot.py save src vNN`。前の版との違いは `snapshot.py diff src vNN`。
- story/shisho-vNN.html の丸ごとの複製は、もう作らなくてよい（控えがあれば組み立て直せる）。

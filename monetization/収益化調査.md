# ポーカーアプリの収益化調査

前提：テキサスホールデムをブラウザで遊ぶ、CPU対戦の1人用アプリ（TypeScript + React/Vite、サーバーなし）。
調査日：2026-10-08

## 結論（おすすめの順番）

1. **まず自分のサイトで公開し、Google AdSense（バナー）＋ H5 Games Ads（ゲーム内のインタースティシャル／リワード広告）を入れる。**
2. **同時に CrazyGames や Poki などのゲームポータルにも出して、広告収益を分けてもらう。** 集客を自力でしなくて済むのが最大の利点。
3. 余裕が出たら「広告を消す買い切り」や「見た目（カード柄・テーブル）の販売」、投げ銭を追加する。
4. **チップを現金で売る・チップに換金性を持たせる、は避ける。** 日本では賭博罪や資金決済法のリスクがあり、個人開発では割に合わない。

## 1. 広告

### Google AdSense（通常のディスプレイ広告）
- サイト全体の審査があり、ゲーム1枚だけのページは「中身が少ない（low-value content）」として落ちやすい。
  - 対策：役の一覧、ルール解説、初心者向け戦略、確率表などの記事ページを用意する。SEO流入にもなる。
- ギャンブルについて：Googleのパブリッシャー制限は「**実際のお金を賭けて、お金や景品を得られる**」ものが対象。日本・米国などは除外国にも入っている。チップに価値がないCPU対戦ポーカーは、この定義には当たらないと読める（ただし規約に「シミュレーションカジノはOK」と明記されているわけではない。推測）。
  - 出典：[Google Publisher Restrictions](https://support.google.com/publisherpolicies/answer/10437795?hl=en)
- 実装：`<script>` タグを入れて広告枠を置くだけ。Viteでも問題なく使える。

### H5 Games Ads（AdSenseのゲーム向け機能）
- ゲームの「区切り」で全画面広告（インタースティシャル）や、「動画を見たらチップ補充」のようなリワード広告を出せる。
- **申し込み制**で、AdSenseの承認済みアカウントが必要。承認は保証されない。
- 実装：AdSense コード＋ Ad Placement API（`adBreak()` を呼ぶだけ）。テスト用に `data-adbreak-test="on"` がある。
- ポーカーとの相性：
  - 「1ハンド終了ごと」ではなく「数ゲームごと」や「トーナメント終了時」にインタースティシャル。
  - 「チップが尽きたら動画を見て補充」がリワード広告の定番の使い方。
- 出典：[H5 Games Ads 概要](https://adsense.google.com/start/h5-games-ads/)、[実装ドキュメント](https://support.google.com/adsense/answer/9955214)、[申し込み方法](https://developers.google.com/ad-placement/docs/signup)

### 単価の目安（第三者ブログの数字、総額・分配前）
- リワード動画：eCPM 約$15〜28（米国）、$8〜15（欧州）
- バナーは一番安く、リワード＞インタースティシャル＞バナーの順。
- 出典：[Cinevva: Web game monetization](https://app.cinevva.com/guides/web-game-monetization)（Playgama 2026 の数字の引用。公式値ではない）

## 2. ゲームポータルで配信する

自分でアクセスを集めるのが一番難しいので、ポータルに載せるのは現実的な選択肢。HTML5ビルドをそのままアップロードできる。

| ポータル | 開発者の取り分（目安） | 備考 |
|---|---|---|
| Poki | 50%（自分で連れてきた流入は100%） | 審査制・Web独占条件あり |
| CrazyGames | 広告60%、課金70%（※ジャム規約の数字） | SDK必須、広告はSDK経由のみ。PEGI 12相当の内容基準 |
| GameDistribution | 純収益の33% | 多数のサイトに配信される |
| itch.io | 90%（自分で設定可） | 買い切り・投げ銭向き |

- 注意：ポータル経由で配信すると、**自前のAdSenseは使えずポータルのSDK広告だけ**になることが多い（CrazyGamesは明記）。自サイト版とポータル版でビルドを分けるのが楽。
- ポーカー（カジノ系）が受け入れられるかはポータルごとの審査次第。CrazyGamesの要件ページにはギャンブル系の記載なし（未確認）。
- 出典：[CrazyGames 要件](https://docs.crazygames.com/requirements/intro/)、[Cinevva まとめ](https://app.cinevva.com/guides/web-game-monetization)
- 収益の現実：ポータルで「そこそこ当たった」カジュアルゲームで月$200〜2,000程度という目安（同ブログ）。

## 3. 広告以外

| 方法 | 内容 | 難易度 | 注意 |
|---|---|---|---|
| 広告除去の買い切り | 数百円で広告オフ | 中 | サーバーなしだと購入状態の保存が課題（後述） |
| 見た目の販売 | カード柄・テーブル・アバター | 中 | ゲームの勝敗に影響しないので法的に安全 |
| 投げ銭 | Ko-fi / Buy Me a Coffee のリンク | 低 | すぐ始められる |
| 有料版 | itch.io で買い切り版 | 低 | 無料版＋有料版の二本立ても可 |
| 将来 | スマホアプリ化して AdMob | 高 | ストアでは「模擬ギャンブル」扱いで年齢制限が上がる |

### サーバーなし構成での課金の問題
- 購入状態を `localStorage` に置くと簡単に改ざん・消失する。
- 現実的な選択肢：
  - Stripe Payment Links / Lemon Squeezy でライセンスキーを発行し、キー入力で解放（改ざんは許容する割り切り）。
  - 本格的にやるなら、その時点で小さなサーバー（Cloudflare Workers や Supabase など）を足す。

## 4. 日本の法律で気をつけること（重要）

※法的助言ではありません。有料要素を入れる前に専門家への確認をおすすめします。

### 賭博罪
- 「お金（や価値のあるもの）を払って、偶然の勝敗で、価値のあるものを得る」形になると賭博に当たりうる。
- **安全な形**：チップは無料で配る・現金で買えない・現金や景品に換えられない・他人に譲渡できない。
- **危ない形**：チップを現金で販売し、勝ったチップで有料アイテムや景品が得られる、など。
- → **チップは売らない**のが一番安全。売るなら「見た目」や「広告除去」のように勝敗と関係ないものにする。

### 資金決済法（ゲーム内通貨を有料で売る場合）
- 有料のゲーム内通貨は「前払式支払手段」に当たりうる。
- 基準日（3月末・9月末）の未使用残高が1,000万円を超えると、届出や残高の半額の供託が必要。
- 有効期限を6か月以内にすると対象外にできる。
- 出典：[モノリス法律事務所 ゲーム規制の解説](https://monolith.law/corporate/game-regulation)

### 景品表示法
- コンプガチャは金額に関係なく禁止。ガチャを入れるなら確率表示を正確に。
- 出典：同上

## 5. 実装メモ（今の構成に入れる場合）

- 広告まわりは `src/ads/` のような1か所にまとめ、`showInterstitial()` / `showRewarded(onReward)` の薄いラッパーにする。自サイト版（AdSense）とポータル版（各社SDK）を差し替えやすくなる。
- 広告ブロッカーで広告が出ないときもゲームが止まらないようにする（リワードが来なければ何もしない）。
- 開発中はテスト広告モードを必ず使う（自分で本番広告をクリックするとアカウント停止リスク）。
- EU向けに出すなら同意管理（CMP）が必要。AdSenseの「プライバシーとメッセージ」で用意できる。

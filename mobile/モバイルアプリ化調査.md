# モバイルアプリとしてリリースするための調査

前提：今のゲーム（1ファイルHTMLのテキサスホールデム、CPU対戦、ストーリーモード「師匠と夜の街」）を、日本の個人開発者として App Store と Google Play の両方に出す。収益は広告＋リワード広告。チップは現金で売らない（[収益化調査.md](../monetization/収益化調査.md)）。
調査日：2026-10-08。規約や期限はよく変わるので、出す直前に出典で再確認すること。※法律・税金の部分は法的助言ではありません。

## 結論

1. **作り方は Capacitor でHTMLをそのままアプリに包むのが一番近道。** 作り直しは不要。ただしWebサイトを表示するだけの「ラッパー」はAppleに落とされやすいので、HTMLはアプリ内に同梱し、オフラインで遊べる・振動・保存などアプリらしさを足す。
2. **広告はAdSenseではなくAdMobに切り替える。** アプリではAdSense／H5 Games Adsは使えない。AdMobは「お金や景品が得られないカジノ系ゲーム（Social Casino Games）」の収益化を認めている。
3. **年齢区分は高めになる前提で考える。** Appleでは「模擬ギャンブルが頻繁」だと **18+**、まれなら13+。ポーカーが主役のアプリは18+になる可能性が高い（推測、最終的には質問票の回答で決まる）。
4. **最初にかかるお金は年1万3千円＋2,500円程度。** Apple は年会費（約12,980円／99ドル）、Google は登録料25ドル（1回だけ）。iOS版のビルドには Mac が必要（クラウドのMacでも可）。
5. **Google Play は公開前に「12人×14日間のテスト」が必須。** 個人アカウントの最大の壁なので、テスターを早めに集めておく。
6. **住所の公開に注意。** Google Play はアプリ内課金などで収益化すると住所が公開される。広告除去の買い切りを売る前に、バーチャルオフィス等を検討。

## 1. 作り方（技術）

| 方法 | 内容 | 向き不向き |
|---|---|---|
| **Capacitor（おすすめ）** | 今のHTML/JSをそのままネイティブアプリの中で動かす。AdMob・保存・振動などはプラグインで追加 | 今のコードをほぼ流用できる。iOS/Android両対応 |
| PWA / TWA | Webアプリとして配布。Androidは TWA で Play ストアに出せる | iOSのApp Storeには出せないので今回は不向き |
| React Native / Flutter / Unity で作り直し | ネイティブで作り直す | 工数が大きい。今の段階では不要 |

### Capacitor でやること
- 今の `shisho.html` を Vite などのプロジェクトに入れ、`npx cap add ios` / `npx cap add android` でアプリの枠を作る。
- **HTMLとフォントはアプリ内に同梱する。** 今は Google Fonts をネットから読んでいるので、オフラインでも見た目が崩れないようフォントファイルを同梱する。
- **セーブデータ：** 今は `localStorage` に保存している。アプリでも動くが、iOSは容量が逼迫すると消すことがあるので、`@capacitor/preferences` に移すと安全。
- **広告：** `@capacitor-community/admob` などのプラグインで AdMob のバナー／インタースティシャル／リワードを出す。収益化調査で決めた「広告まわりを `showInterstitial()` / `showRewarded()` の薄いラッパーにする」方針なら、Web版とアプリ版で差し替えるだけで済む。
- 画面：スマホ縦持ち、ノッチ（セーフエリア）、戻るボタン（Android）への対応。
- **Xcode：** 2026年4月28日以降、App Store に出すアプリは Xcode 26 以降・iOS 26 SDK でビルドする必要がある（[Apple](https://developer.apple.com/news/upcoming-requirements/)）。
- **Android の対象APIレベル：** 2026年8月31日以降、新規アプリと更新は Android 16（API 36）以上が必須（延長申請で11月1日まで）（[Android Developers](https://developer.android.com/google/play/requirements/target-sdk)）。毎年上がるので、出す年の要件を確認。

### Mac がない場合
- iOS のビルドと提出には macOS 上の Xcode が要る。Mac がなければ Codemagic や GitHub Actions の macOS 環境などクラウドでビルドする方法がある（実機での確認は iPhone があれば TestFlight で可能）。

## 2. アカウントと費用

| | Apple（App Store） | Google（Google Play） |
|---|---|---|
| 登録費 | 年会費 99ドル（日本では約12,980円）。毎年更新 | 25ドル（1回だけ） |
| 本人確認 | Apple ID＋本人確認 | 身分証による本人確認。個人アカウントは法的氏名・国・メールが公開される |
| 公開前の条件 | 審査（通常1〜数日） | **2023年11月13日以降に作った個人アカウントは、12人以上が14日間連続でクローズドテストに参加していないと本番公開を申請できない**（[Google](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)） |
| 手数料 | 売上の30%。年100万ドル以下なら Small Business Program で15% | 売上の15%（年100万ドルまで） |

- 手数料はアプリ内課金にかかるもので、**広告収益（AdMob）にはかからない**。
- テスターは家族・友人や、開発者同士でテストし合うコミュニティで集めるのが一般的。14日の待ちがあるので、Android は早めにクローズドテストを始める。

## 3. ストアの規約（ポーカーアプリ特有の点）

### 「模擬ギャンブル」として扱われる
- Apple の定義：「現金や、現金に換えられるゲーム内通貨を使わない賭け」＝ Simulated Gambling。このアプリはこれに当たる。
- **Apple の年齢区分**（2025年から 4+ / 9+ / 13+ / 16+ / 18+ の5段階）：模擬ギャンブルが「まれ」なら 13+、「頻繁」なら 18+（[Apple 年齢区分の定義](https://developer.apple.com/help/app-store-connect/reference/app-information/age-ratings-values-and-definitions/)）。ポーカーが遊びの中心なので「頻繁」と答えるのが正直で、18+ になる見込み（推測）。
  - 18+ だと子どもには表示されにくくなるが、ルールを偽って低くすると審査落ち・削除の原因になる。
- **Google Play** は IARC という共通の質問票に答えると、国ごとの年齢区分が自動で付く。模擬ギャンブルがあると高めの区分になる（具体的な区分は回答次第）。
- どちらでも共通で守ること：
  - **現金や景品に換えられるものを一切出さない**（チップを売らない方針はそのまま有効）。
  - **本物のオンラインカジノに誘導しない**（Google は「実際のお金のカジノへ誘導する模擬カジノ」を違反例に挙げている）（[Google Play 規約](https://support.google.com/googleplay/android-developer/answer/9877032)）。
  - 子ども向けプログラム（Google の「ファミリー向け」）には参加しない。対象年齢を「18歳以上」などに設定する。

### Apple の「最低限の機能」ルール（4.2）
- Webサイトを表示するだけのアプリは却下されやすい。HTMLを同梱し、オフラインで遊べるゲームとして出せば普通は問題になりにくい。
- ポーカーアプリはストアに大量にあるので、「似たアプリの量産（4.3 スパム）」と見られないよう、ストーリーモードやキャラクターを説明文とスクリーンショットで前面に出す。

## 4. 広告（AdMob）

- アプリでは **AdMob** を使う。AdSense / H5 Games Ads はWeb専用。
- AdMob は「Social Casino Games」（お金や景品が当たらない模擬ギャンブル）を広告カテゴリとして扱っており、**このようなアプリ自体の収益化は認められている**（[AdMob ヘルプ](https://support.google.com/admob/answer/6166400?hl=en)）。
- 模擬ギャンブルのアプリには「ギャンブル広告」は表示できない（Google Play 規約）。普通の広告が出るだけなので実害は小さい。
- **iOS は ATT（トラッキング許可ダイアログ）が必要。** 「このアプリが他社のアプリやサイトを横断してトラッキングすることを許可しますか」の表示。拒否されると広告単価が下がる。
- **EU・英国向けに出すなら同意画面（CMP）が必要。** AdMob の「プライバシーとメッセージ」で用意できる。面倒なら最初は日本など一部の国だけで配信してもよい。
- リワード広告の使い方は Web 版と同じ（「チップが尽きたら動画を見て補充」など）。
- 開発中は必ずテスト広告ID を使う（自分で本番広告をタップするとアカウント停止のリスク）。

## 5. 提出に必要なもの（チェックリスト）

- [ ] アプリ名・説明文・キーワード（日本語、できれば英語も）
- [ ] アイコン（1024×1024）、スクリーンショット（iPhone／Android スマホ。iPad対応するならiPadも）
- [ ] **プライバシーポリシーのURL**（両ストア必須。AdMob が広告ID等を使うことを書く）
- [ ] サポート用URLまたはメールアドレス
- [ ] Apple「App のプライバシー」、Google「データ セーフティ」の申告（AdMob が集めるデータを申告する）
- [ ] 年齢区分の質問票（模擬ギャンブル：頻繁）
- [ ] `app-ads.txt` を自分のWebサイトに置く（AdMob の広告収益を守るため。Web 版のサイトがあればそこに置ける）
- [ ] Google Play：クローズドテスト（12人×14日）
- [ ] iOS：TestFlight で実機確認

## 6. お金・税金・個人情報

- **住所の公開：** Google Play は個人アカウントでも「収益化」すると住所全体が公開される（[Google](https://support.google.com/googleplay/android-developer/answer/13628312?hl=en)）。広告のみの無料アプリは対象外と読めるが、広告除去の買い切りなどアプリ内課金を始めると公開される（推測を含む）。Apple も EU で配信する場合は「トレーダー」として住所などの公開を求められる。自宅を出したくなければ、バーチャルオフィスの住所を使うか、EU を配信対象から外す。
- **確定申告：** 会社員の副業なら、所得（収入−経費）が年20万円を超えると確定申告が必要。本格的にやるなら開業届＋青色申告で控除が受けられる。登録費・Mac・素材代などは経費にできる。
- **米国の税務フォーム：** Apple・Google・AdMob の支払い設定で米国税務情報（W-8BEN）を提出する。日本居住者は租税条約で源泉徴収が軽減される。
- **アプリ内課金を始める場合：** 特定商取引法の表記ページを用意する開発者が多い。消費税・インボイスまわりは売上規模で変わるので、その段階で税理士に確認するのが安全。
- **スマホ新法：** 2025年12月から「スマホソフトウェア競争促進法」が全面施行され、日本ではストア外決済や別ストアの選択肢が広がった。個人開発の最初の段階では、通常の App Store / Google Play の仕組みのままで十分。

## 7. 進め方の目安

1. Web 版を完成させ、Web で反応を見る（今の方針どおり）。
2. Capacitor プロジェクトを作り、Android 実機で動かす（Mac 不要で一番早い）。
3. Google Play に登録し、クローズドテスト（12人×14日）を開始。その間に AdMob を組み込み、プライバシーポリシー等を用意。
4. Apple Developer に登録し、Mac（またはクラウドビルド）で iOS 版を作って TestFlight で確認。
5. 両ストアへ提出。最初は日本向け（＋英語圏）だけに絞ると、同意画面などの手間が減る。

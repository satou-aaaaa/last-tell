# UI/UXレビューの手順（2026-10-10 satou「UI/UXのレビューも都度やるように」）

新しい版を公開するたびに行う。クリエイター目線のレビュー（[クリエイター目線レビューの手順.md](クリエイター目線レビューの手順.md)）と**同じスレッドで続けて**行い、1つのスレッドで両方を出す。

## 3つの層

| 層 | 何をするか | どこに出るか |
|---|---|---|
| 1. 画面の崩れ（自動） | 重なり・はみ出し・隠れ・文字切れ・横スクロール。12場面 × スマホ縦 390×844・横 844×390・PC 1280×800 | `qa/checks/ui.js` → report.md「画面チェック」。新しい問題は ❌ |
| 2. 使いやすさの数字（自動） | 下の8項目を同じ12場面 × 3画面で測る | `qa/checks/uiux.js` → report.md「使いやすさの数字」、生の数字は `uiux.json`。前の版より悪くなったら ⚠️、目標に届いていないだけなら 🟡 |
| 3. 目で見るレビュー（毎回） | `ui/` の画像と、変わった所を実際に触って、下の10観点で見る | `qa/reports/v<版>/uiux.md` |

どちらの自動検査も `sh qa/run_all.sh` に入っている（追加の手間なし）。

### 2. 使いやすさの数字（uiux.js）

| 項目 | 目標 | 出どころ |
|---|---|---|
| 大事な部品が最初の画面にある（降りる・受ける・上げる、自分の手、相手の名札、タイトルの3ボタン、レイズ欄を開いたときの相手の名札） | 外れ0 | UI整理 案3 §6 |
| 押しやすい大きさ | スマホ44px・PC24px以上 | Apple/Google の目安、WCAG 2.5.8 |
| 文字の大きさ | 12px以上 | 読みやすさの目安 |
| 文字と背景の明るさの差 | 4.5:1以上（大きい字は3:1） | WCAG 1.4.3。背景が画像・グラデーションの所は測れないので目で見る |
| 記号だけのボタンに名前がある | aria-label か title | 読み上げ・英語版 |
| 対戦中の画面が1画面に収まる | 1.0画面 | UI整理 案3 §6 |
| 最初の画面で押せる部品の数 | 前の版より増えない（+2まで） | ごちゃごちゃ度（クリエイター目線の観点6） |
| 吹き出しの同時表示 | 1つまで | UI整理 案3 §6 |

- 基準は `baseline.json` の `uiux`（今は v62 の値）。版を公開して問題ないと決めたら `--update-baseline` でほかの基準と一緒に書き直す。
- UI整理 案3 が入ると「1画面」「最初の画面」の数字は大きく良くなるはず。良くなったのに 🟡 のままなら、案3 の作りを見直す。

### 3. 目で見る10の観点（uiux.md）

変わった所だけを見る。各観点を「◎よくなった／○変わらない／△気になる／✕止めたい」で1〜2行。変わっていない観点は「○」だけでよい。

| # | 観点 | 見ること |
|---|---|---|
| 1 | 見る順番 | 相手の顔 → 場の札とポット → 自分の手 → ボタン、の順に目が動くか。一番目立つものが一番大事なものか |
| 2 | 今の状態 | 誰の番か、いくら払えば続けられるか、自分のチップ、が1秒で分かるか |
| 3 | 押した手応え | 押したら何が起きたかすぐ分かるか（音・動き・文字）。押せないボタンは押せないと分かるか |
| 4 | 指の届く所 | スマホ縦で、よく押すボタンが親指の届く下半分にあるか。横画面で両手持ちのまま押せるか |
| 5 | 間違えにくさ | 全額・降りるなど取り消せない操作の前で止まるか。チェックできるのに降りられてしまわないか |
| 6 | そろっているか | 色・言い回し・ボタンの位置が画面ごとにそろっているか（降りる・受ける・上げるの並び、閉じる✕の位置） |
| 7 | 読みやすさ | 文字の大きさ・明るさの差（数字の🟡項目の中身を目で確かめる）。吹き出しや案内が顔に重なっていないか |
| 8 | 情報の量 | 同じことを2回以上出していないか（結果の文字など）。今いらないものが前に出ていないか |
| 9 | 画面の大きさごと | 横画面とPCで空いた場所の使い方。PCで卓が小さすぎないか |
| 10 | 英語版 | 文字切れ・はみ出し、ボタンの言葉が短く分かるか |

- 見た目の方向（黒・深紅・金、斜めに切ったボタン、「かっこいい・クール」）を崩す直しは出さない。

## 結果の扱い

- **小さい直し**（大きさ・余白・言い回し・位置）→ 本線に渡す（UI整理 案3 の範囲なら、その作業に足す）。
- **大きい直し**（画面の作り替え、機能を消す・動かす）→ satou さんに選んでもらう（プロジェクトのチャットにも出す）。
- 自動で測れる形にできた問題は `uiux.js` か `ui.js` に項目を足す。以後は毎回自動。
- クリエイター目線の観点5（画面の読みやすさ）と6（量）は、こちらの結果を引用する（同じことを2か所に書かない）。

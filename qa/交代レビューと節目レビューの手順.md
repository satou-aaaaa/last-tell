# 交代レビューと節目レビューの手順（2026-10-10 satou 決定：案1＋2＋3）

もとの提案：[research/レビューの仕組みを充実させる_提案.md](../research/レビューの仕組みを充実させる_提案.md)。
毎回のクリエイター目線レビュー（[クリエイター目線レビューの手順.md](クリエイター目線レビューの手順.md)）と UI/UXレビュー（[UIUXレビューの手順.md](UIUXレビューの手順.md)）に、**1つの視点を交代で深く見る**レビューと、**節目の通しレビューの視点**を足すものです。自動で確かめられる所は `qa/run_all.sh` に入っています（案1、下の「自動の検査」）。

## 1. 版ごとの交代レビュー（案2）

- **いつ・どこで**：新しい版を公開したあと、クリエイター目線＋UI/UXレビューと**同じスレッドで続けて**行う。本線の作業は止めない。
- **どの視点か**：版の番号で決める（v63 から）。

| 版の番号を5で割った余り | 視点 | 版の例 |
|---|---|---|
| 3 | 物語・台本 | v63, v68, v73 |
| 4 | ポーカーの正しさ | v64, v69 |
| 0 | 初めての人 | v65, v70 |
| 1 | 英語版 | v66, v71 |
| 2 | アクセシビリティ | v67, v72 |

- 物語が大きく変わった版（新しい章・会話の追加）は、決まった視点に加えて「物語・台本」も短く見る。
- **見る範囲**：前の版から変わった所が中心。変わった所が少なければ、その視点で前から気になっている所も見る。
- **結果**：`qa/reports/v<版>/rotate.md` に1枚（下のひな形）。
- **その後**：小さい直し（言い回し、訳、表記）は本線に渡す。物語の筋・機能を変えるものは satou さんに選んでもらう（プロジェクトのチャットにも出す）。
- 機械で確かめられる形にできたものは、`qa/checks/` に項目を足す（以後は毎回自動）。
- 重ねないこと：UI/UXレビューで見た所（崩れ、押す大きさ、明るさの差）は uiux.md を引用する。改善提案（自動）＝足すと良くなるもの、交代レビュー＝今の版が悪くなっていないか。

### 視点ごとに見ること

**物語・台本**
- まず report.md の「台本」を見る（一人称のずれ、言ってはいけない言い方、使い回し、長すぎるセリフ、英語に訳せないセリフ）。⚠️ は中身を読んで「直す／このままでよい」を決め、よいものは次の基準に入れる。
- 変わったセリフを [story/キャラクター作りこみ案.md](../story/キャラクター作りこみ案.md) の「話し方の早見表」と [story/口癖案.md](../story/口癖案.md) と並べて読む。キャラの声になっているか。
- 伏線と回収（[research/長編の伏線3つ_実装仕様.md](../research/長編の伏線3つ_実装仕様.md)、[story/ストーリー練り直し案.md](../story/ストーリー練り直し案.md)）と食い違っていないか。
- 章の締めの1行が効いているか。勝ち負けの決まり文句（「勝ち +◯◯」など）が静かな場面を壊していないか。
- 決まりごと：「夜」を名前に使わない・「あの日」、セリフにお金の話を入れない、第7章に掛け合いを入れない。

**ポーカーの正しさ**
- report.md の「ルールの基本」「プロポーカー目線の再発チェック」を見る。
- 変わった所（新しい店のルール、CPU、配り札固定）を実際に打ち、[research/ノーリミットホールデムのルール.md](../research/ノーリミットホールデムのルール.md) とずれていないか。ジンの助言・1行の案内が、ポーカーとして正しいことを言っているか。
- CPU が強さの順に見えるか（強いキャラが雑な打ち方をしていないか）。

**初めての人**
- ポーカーのルールを知らない人のつもりで、新しいセーブ（スマホ縦 390×844）から第1章を遊ぶ。
- 説明より先に出てくる言葉（ブラインド、ポット、キッカー、オールイン…）を書き出す。「ポーカーは初めて？」と1行の案内で足りているか。
- report.md の ftue（最初の判断までの回数）を前の版と比べる。迷う所・押し間違えそうな所。

**英語版**
- 設定で English にして、変わった所を読む。report.md の「英語版に残っている日本語」と「台本：英語に訳せないセリフ」も見る。
- ポーカー用語が英語圏の言い方か（Fold / Check / Call / Raise / All-in、Small blind、Pot、Showdown など）。キャラの口調（ジンの短さ、クロウの丁寧さ）が英語でも出ているか。
- 文字切れ・はみ出しは uiux.md の観点10を引用する。

**アクセシビリティ**
- report.md の「アクセシビリティ（uiux の残り）」を見る。
- 音を切って遊ぶ（自分の番・オールイン・勝ち負けが文字や動きで分かるか）。端末の「視差効果を減らす／動きを減らす」をオンにして遊ぶ。
- 4色のトランプ・文字の大きさ（プロ目線 B4）が入った版では、それをオンにして崩れないか。
- 明るさの差・押す大きさは uiux.md を引用する。

## 2. 節目の通しレビュー（案3）

クリエイター目線の通しレビュー（[クリエイター目線レビューの手順.md](クリエイター目線レビューの手順.md) §3）に、次を足します。どれも**まっさらなセーブ**から、`sh qa/run_all.sh --full` の結果を見たうえで行います。

| 節目 | 足す通しレビュー | 結果 |

## 3. 自動の検査（案1）

`sh qa/run_all.sh` に入っています。くわしくは [qa/README.md](README.md)。

| 検査 | 見ること | 短い版／長い版 |
|---|---|---|
| script（台本） | 一人称、言ってはいけない言い方、同じセリフの使い回し、長すぎるセリフ、英語に訳せないセリフ。新しく増えたら ⚠️ | 両方 |
| basics（ルールの基本） | 役の判定（別に書いた判定と比べる）、最低レイズ、足りないオールイン、SB・BBの席と額、最初に話す人、ショーダウンの配り方 | 両方（長い版は第6章・第二部も） |
| save（セーブの引き継ぎ） | 保存される鍵が全部 SAVE_KEYS にあるか。前の版の控え（dev/snapshots/）で遊んだセーブを新しい版で開き、消えない・進みが戻らない・続けて遊べる・引き継ぎコードが往復する | 短い版は1つ前の版、長い版は全部の控え |
| a11y（アクセシビリティの残り） | カードのマークが字で出ている、4色にできる、「動きを減らす」で動き続けるものがない | 両方 |
| perf（重さ・速さ） | CPU 4倍遅くで起動の時間。長い版は120ハンド打って引っかかりの回数とメモリの増え方 | 起動は両方、打つのは長い版 |
| winrate（広げた分） | 第5〜7章・第11〜15章の勝率を記録（変わっても ⚠️ だけ） | 長い版 |

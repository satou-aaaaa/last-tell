# LAST TELL 変更後の検査（qa/）

ゲーム（story/shisho.html）を変えたら、毎回これを回します。2026-10-10 satou さんが「案1＋案2」を選んだもの。

## 回し方

```
sh /mnt/project-files/qa/run_all.sh                      # 短い版（毎回の変更で）
sh /mnt/project-files/qa/run_all.sh --full               # 長い版（テスト公開・ストア提出の前）
sh /mnt/project-files/qa/run_all.sh 別のファイル.html     # ファイルを指定
node /mnt/project-files/qa/run_all.js --only fuzz,ui     # 一部だけ（text, ftue, fuzz, rules, winrate, ui）
```

- 結果は `qa/reports/v<版>/report.md`（画面の画像は `ui/`）。不合格があると終了コード 1。
- 必要なもの：Node と Playwright（クラウドの作業環境には入っている。GitHub では自動で入れる）。

## 中身

| 検査 | 見ること | 出どころ |
|---|---|---|
| text | 「あの夜」が無い、名前（章・店・称号・ボタン）に「夜」が無い、会話にお金の話が無い | satou さんの決めごと |
| ftue | タイトルから最初の判断まで5回以内、章の途中で閉じても「続きから」 | クリエイター目線 S1・S3 |
| fuzz | 全モード（第1〜7章、第11〜15章、フリー4人/6人と店のルール、店で遊ぶ、裏の卓、はしご、英語版）を自動で打って、止まらない・エラーが出ない・チップの合計が合う。英語版で日本語が残っていないか | これまでの自動対戦 |
| rules | BBアンティが返らない、トーナメントで2回めくり・ボムポットが出ない、強キャラがリンプしない、3BBに降りすぎない、リバーの2倍ベットにコールしすぎない | プロポーカー目線 S1・S2・A1・A2 |
| winrate | 第1〜4章の勝率が前の版と同じくらい（第1〜3章は変わったら不合格） | 「第1〜3章の難しさは変えない」 |
| ui | スマホ縦 390×844・横 844×390・PC 1280×800 で12場面を撮って、重なり・はみ出し・隠れ・文字切れ・横スクロールを自動で探す | 画面チェックの決めごと、テスター目線 |

## 結果の見方

- ✅ 合格　❌ 新しく起きた問題（公開を止める）　⚠️ 気にかけること　🟡 修正待ち、または前の版からある問題
- `known.json`：修正待ちの項目（仕様は決まっていて、まだ入っていないもの）。直ると報告に「直った」と出るので、そのとき外す。
- `baseline.json`：前の版の基準（勝率、前からある画面の問題、英語版の既知の取りこぼし、前からあるセリフ）。新しく増えたものだけを ❌ にするため。
  - 版を公開して問題がないと決めたら `node qa/run_all.js --full --update-baseline` で書き直す。

## 新しい問題が見つかったら

検査を1つ足します（checks/ のどれかに項目を足す）。以後は毎回自動で確かめられます。直す前なら known.json にも足します。

## 目で見る検証（大きな変更のときだけ）

新しい章・新しい仕組み・画面の作り替えのときは、自動検査に加えて、変わった所だけをテスター目線・プロポーカー目線・クリエイター目線で見ます。見つかったことは、機械で確かめられる形にして上の検査に足します。

## GitHub（テスト公開）での自動実行

テスト公開のリポジトリ satou-aaaaa/last-tell の `.github/workflows/qa.yml` が、index.html が変わったプルリクエストとプッシュのたびに短い版を回します。結果は GitHub の Actions 画面に ✅/❌ で出て、報告と画像は「qa-report」としてダウンロードできます。

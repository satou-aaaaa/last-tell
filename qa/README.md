# LAST TELL 変更後の検査（qa/）

ゲーム（story/shisho.html）を変えたら、毎回これを回します。2026-10-10 satou さんが「案1＋案2」を選んだもの。

## 回し方

```
sh /mnt/project-files/qa/run_all.sh                      # 短い版（毎回の変更で）。結果は reports/_runs/ の新しいフォルダ
sh /mnt/project-files/qa/run_all.sh --full               # 長い版（テスト公開・ストア提出の前）
sh /mnt/project-files/qa/run_all.sh 別のファイル.html     # ファイルを指定
node /mnt/project-files/qa/run_all.js --only fuzz,ui     # 一部だけ（text, ftue, fuzz, rules, winrate, ui, uiux）
node /mnt/project-files/qa/run_all.js 作った.html --changed v62 [--src 作業場所/src]
                                                         # 変えた所だけ（作業の途中で。控え v62 と比べて検査を選ぶ）
node /mnt/project-files/qa/run_all.js --only winrate --ch 1,2   # 勝率を章を選んで
sh /mnt/project-files/qa/run_all.sh --official [--full]   # 版の正式な結果（本線だけ）→ reports/v<版>/
node /mnt/project-files/qa/run_all.js --list              # 検査の一覧
```

- **結果の置き場所（2026-10-10 CIの見直し 案1）**：ふだんは `qa/reports/_runs/<日時>_<ファイル名>_<版>_<番号>/` に、毎回別のフォルダで書く。だれが何回回しても重ならない。1日たったら次に回したときに消える。最後に「結果の置き場所:」と出る。
  - `qa/reports/v<版>/` と `baseline.json` に書くのは `--official` のときだけ。**本線だけが使う**（`--only`・`--changed`・`--ch`・`--out` とは一緒に使えない）。同じ版の `--official` が同時に2つ走ると、後のほうは止まる。
  - 今日（2026-10-10）レーンの試作の検査が reports/v63/ を2回上書きしたため。
- **勝率の乱数は固定**（案3）：i 回目はいつも同じ配り方。同じファイルなら何度回しても同じ勝率になるので、基準と違えば本当に変わった。result.json の `games`（W/L の並び）で1回ずつ比べられる。

- `--changed`（2026-10-10 開発スピード 案2）：変わった src のファイルから回す検査を選ぶ（qa/lib/changed.js の表）。見た目だけなら ui・uiux と安い検査で数分。勝率（約15分）は CPU・章・配り札（02・10・14・15・25）を変えたときだけ。どの検査に関わるか決めていないファイルがあれば全部回す。結果は `reports/v<版>_changed/`、基準は書き換えない。**版を出す前は必ず `--changed` なしで全部を回す。**
- 結果は `report.md`（画面の画像は `ui/`）。不合格があると終了コード 1。
- 必要なもの：Node と Playwright（クラウドの作業環境には入っている。GitHub では自動で入れる）。

## 結果の見方

- ✅ 合格　❌ 新しく起きた問題（公開を止める）　⚠️ 気にかけること　🟡 修正待ち、または前の版からある問題
- `known.json`：修正待ちの項目（仕様は決まっていて、まだ入っていないもの）。直ると報告に「直った」と出るので、そのとき外す。
- `baseline.json`：前の版の基準（勝率、前からある画面の問題、英語版の既知の取りこぼし、前からあるセリフ）。新しく増えたものだけを ❌ にするため。
  - 版を公開して問題がないと決めたら `node qa/run_all.js --official --full --update-baseline` で書き直す（本線だけ）。

## 新しい問題が見つかったら

検査を1つ足します（checks/ のどれかに項目を足す）。以後は毎回自動で確かめられます。直す前なら known.json にも足します。

## 目で見る検証（大きな変更のときだけ）

新しい章・新しい仕組み・画面の作り替えのときは、自動検査に加えて、変わった所だけをテスター目線・プロポーカー目線・クリエイター目線で見ます。見つかったことは、機械で確かめられる形にして上の検査に足します。

## GitHub（テスト公開）での自動実行

テスト公開のリポジトリ satou-aaaaa/last-tell の `.github/workflows/qa.yml` が、index.html が変わったプルリクエストとプッシュのたびに短い版を回します。検査は組に分けて同時に回し（勝率は章ごと）、実行機は ubuntu-24.04 に固定しています。**新しい検査を足したら qa.yml の組（QA_GROUPS）にも足す**（入れ忘れると「検査の一覧」が ❌ になる）。結果は GitHub の Actions 画面に ✅/❌ で出て、報告と画像は「qa-report」としてダウンロードできます。

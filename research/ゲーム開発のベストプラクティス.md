# ゲーム開発のベストプラクティス（LAST TELL Godot 版に当てはめ）

2026-10-23 調べ（スレッド「ゲーム開発のベストプラクティス」）。対象：Godot 4.7・PC（Windows、Steam 候補）・物語つきポーカー・satou さん1人＋AI のスレッドたち・自前ランナーの CI・MetaHuman の 3D キャラ・VOICEVOX の声。

## 結論

- **作りの土台はもう業界の良いやり方に沿っている**（流れと画面を分ける・知らせで機能を足す・自動照合と CI・保存の壊れ対策・ログ・キーボード操作・字の大きさ・クレジット）。
- **足りないのは「量が増える前の決まり」と「出す前の段取り」**。とくに次の 4 つが先：
  1. **縦切り（バーティカルスライス）を次の目標にする**：第1章だけを MetaHuman＋声＋本物の卓で「売れる品質」まで作り切り、そこで重さ・作業量・見た目を測ってから残りに広げる。
  2. **大きいファイルの決まり**（3D・声で git が重くなる前に）→ **今日入れた**（検査）。
  3. **重さの予算と最低環境**を数字で決める（60fps＝1こま 16.7ms）。
  4. **音量を3本（音楽・効果音・声）に分ける・キーの割り当てを変えられる**（声が入る前に）。

## 1. 今やっていること（良い所）

## 2. 足りない所（優先順）

### 2-1 段取り：縦切り → アルファ → ベータ → 1.0（おすすめ ◎）
- いま：1.0 の範囲（dev/1.0の範囲.md）はあるが、**区切りごとの「できたの条件」と「ここからは足さない」日付がない**。MetaHuman 54人・全台詞の声は量が大きく、作り方を決めないまま広げると作り直しが増える。
- 専門家：Derek Yu（Spelunky）「どんな手を使っても、まず終わらせる」「小さく出して、少しずつ大きく」。Balatro（1人で約3年）は締め切り前に体を壊したと作者が書いている＝**量の見積もりと削る決まりが先**。
- 提案：
  - **縦切り**：第1章（ジン＋3〜5人）を 3D・声・本物の卓・音・UI すべて最終品質で。ここで「1人の 3D 化に何時間」「声1章で何本」「重さ」を測り、残りの計画を数字で引き直す。
  - **アルファ**：全章が最後まで通る（仮の絵・仮の声でよい）。**ここで機能を締める（新しい機能は 1.0 後へ）**。
  - **ベータ**：全部の絵・声・文が入る（**内容を締める＝content lock**）。直すのはバグと読みやすさだけ。外のテスターに渡す。
  - **1.0**：satou さんの決めた公開の基準（dev/できたの条件と公開の基準.md）を満たす。

### 2-2 大きいファイル（今日入れた ✅）
- GitHub は 1 ファイル 50MB で警告、100MB で push を断る。Git LFS の無料枠は保存 10GiB・ダウンロード 10GiB/月（自前ランナーの取り直しも数える）。いまの repo は 163MB（圧縮後）、作業中のファイルの合計 255MB。
- 入れた検査 `tools/check_big_files.sh`（qa.sh から）：50MB 超は NG（LFS の印があれば通す）、20MB 超は ⚠、**Unreal・Blender・Photoshop などの元ファイル（.uasset .umap .blend .psd …）は NG**。元ファイルは satou さんの PC の D: に置き、ゲームで使う書き出し（.glb・.webp・.ogg）だけ入れる。
- 次：3D キャラが 1 人 20MB を超えそうなら、そのとき LFS（*.glb）を入れるか決める。

### 2-3 重さの予算と最低環境（◎）
- いま：卓の重さの検査は「1こま 50ms 超えが2回以上で NG」。satou さんの PC（GTX 1070）で平均 11ms。**目標の fps と最低環境が決まっていない**。
- 業界：60fps なら 1こま 16.7ms。Godot 公式も「推測せず測る（プロファイラ・Monitor）」。3D キャラ 6 人が並ぶ卓は、MetaHuman のままだと重い（髪・肌・高い LOD）。
- 提案：最低環境を「GTX 1050 Ti か Intel Iris Xe 程度・メモリ 8GB・1280×720」と置く（Steam の調査で多い層）。予算：卓の場面 16.7ms（最低環境は 33ms＝30fps）、3D キャラ 1 人あたり三角形 3〜5万・テクスチャ 2K まで・6 人＋ディーラーで VRAM 1.5GB 以内。bench に「平均 16.7ms 超えは ⚠」を足す。

### 2-4 音量3本・キー割り当て・字幕（◎、声が入る前に）
- Game Accessibility Guidelines の「基本」：**音楽・効果音・声を別々に調整**、**キーの割り当てを変えられる**、**大事な声には字幕**、設定は全部保存。
- いま：「音」が オフ／効果音だけ／すべて の3段。キーは固定。
- 提案：設定に「音楽・効果音・声」の3本の音量（Godot の AudioBus を3本に）。キーの割り当て（InputMap を設定に保存）。声のある台詞は字幕を必ず出す（いまの字幕のまま、声オフでも出る）。

### 2-5 保存の場所と版の上げ方（○）
- いま：Godot の既定の場所（Windows は %APPDATA%\Godot\app_userdata\LAST TELL）。各キーに "v":1 はあるが、v が上がったときに古い保存を直す手順（移し替え）がない。
- 提案：project.godot の `application/config/use_custom_user_dir` で **%APPDATA%\LAST TELL** に固定（Steam Cloud・テスターへの案内が楽。変えるのは早いほど良い）。保存の読み込みに「v ごとの直し方」の表を置き、古い版の保存を検査で読む（check_save.gd に v0 の見本を足す）。保存に Godot の Resource を使わない（読み込みでコードが動きうる。いまの JSON のままで良い：GDQuest）。

### 2-6 版番号と変更の記録（○）
- いま：data/APP_VERSION.json が "0.98.9"（Web 版の版）。
- 提案：Godot 版の版を別に（例 0.99.0 から、ベータで 0.99.x、公開で 1.0.0）。PR のマージで CHANGELOG.md に1行。Steam を使うなら枝（default・beta・playtest）と版を対応させる。

### 2-7 試遊とデータ（○、ベータで）
- 専門家：Slay the Spire（Mega Crit、GDC 2019「Metrics Driven Design and Balance」）は、遊ばれた記録の数字で難しさを合わせ続けた。
- 提案：外のテスターに渡すときは、①自分から送る「遊んだ記録」（どの章で止めたか・負けた回数・遊んだ時間。いまの shisho-stats を書き出すボタン）②短い感想の表、を付ける。勝手に送る仕組み（テレメトリ）は入れない。Steam を使うなら Steam Playtest（無料の別アプリ、人数を絞れる）か、合言葉つきのベータ枝。

### 2-8 落ちたときの報告（△、ベータで）
- いま：手元のログと「前回落ちました」の案内。テスターのログは手で送ってもらう必要がある。
- 候補：Sentry の Godot 用 SDK（Windows・Linux、無料枠あり、アカウントが要る＝satou さんの手）。ベータの前に決める。

### 2-9 Steam（お金がかかる＝聞いてから）
- Steam の登録料（Steam Direct）は 1 作 100 ドル。専門家（Chris Zukowski、howtomarketagame）：ストアの「近日公開」ページは早めに出してウィッシュリストを集める。公開日は Next Fest（2・6・10月）と大きなセールの週を避け、月曜か水曜。人気の近日公開に載るには 6,000〜7,000 のウィッシュリストが目安。
- 提案：縦切りができたら、ページ・Next Fest の体験版を相談する。

### 2-10 権利・表示（○）
- **VOICEVOX**：ソフト自体は無料で商用も可だが、**キャラ（声）ごとに規約がちがう**。クレジットは「VOICEVOX:キャラ名」を使う声すべて。禁止の使い方（政治・宗教・成人向け・誹謗など）もキャラごと。**ポーカー（ギャンブル風）の物語で使ってよいか、選んだ声それぞれの規約を確かめる**。credits.json に声を足し、検査に載せる。
- **MetaHuman**：2025年6月から Unreal 以外（Godot）でも使える。年の売上 100 万ドル未満は無料、Unreal Engine の EULA に従う。AI の学習に使うのは不可。
- **Steam の内容の申告**：成人向けの内容は申告が要る。現金に換えられないポーカーは賭博ではないが、ストアの説明に「現金や景品には換えられません」と書くと安心（すでに「チップを現金で売らない」と決めている）。

### 2-11 細かいもの（△）
- GDScript の型：Godot 公式の警告（untyped_declaration など）を ⚠ で数え、新しいファイルは型をつける。急がない。
- 英語の字あふれ：Godot の「疑似ローカライズ」（文を長くして崩れを見る）で英語の前に崩れを見つけられる。1.0 は日本向けなので後回し。

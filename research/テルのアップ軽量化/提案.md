# テルのアップ演出がスマホで重い：原因と直し方（2026-10-10）

## 原因
アップのとき、キャラ絵（SVG）にかかっている**影3重**（`.bust .body svg` の drop-shadow、うち1つは 9px のぼかし影）を、
2.7倍に拡大した大きさで毎コマ描き直している。スマホは画面の細かさ（DPR 3）もあるので、描く量がPCの何倍にもなる。
寄っている間もキャラは呼吸・揺れのアニメで動いているため、影の描き直しが止まらない。

最初に疑った「周りの席のぼかし（blur 1.5px）」「端末の傾きで背景を動かす処理」「カメラの transform」は、測ると小さかった。

## 測り方
スマホ縦 390×844・DPR 3・CPU 4倍遅く（安いスマホ相当）。6人卓で CPU の番に止め、
「寄る（1.0秒）→ テルへ寄り直す（1.3秒）→ 戻る」を、手持ちの傾きの揺れを入れて流し、1コマの時間を数えた。各2回。
スクリプト: `measure.js`（このフォルダ）。ヘッドレスの Chrome なので数字は実機そのものではなく、**前と後の比べ**として見る。

| やり方 | テルのアップ中 | 50ms以上止まったコマ（アップ中） | 演出全体 |
|---|---|---|---|
| 今 | 16〜18 fps | 11〜13 | 19〜23 fps |
| 周りのぼかしをやめる | 18 fps | 10〜13 | 23 fps |
| 寄っている間キャラの動きを止める | 15〜17 fps | 9〜13 | 19〜20 fps |
| カメラに will-change | 17〜18 fps | 10〜13 | 20〜22 fps |
| **案1：寄っている間だけ、ぼかし影を外す＋暗くした席の影を外す** | **33〜34 fps** | **0〜2** | **31〜35 fps** |
| 影を全部外す（輪郭の光も消える） | 31〜34 fps | 1〜2 | 30〜33 fps |
| 案1＋ぼかしも外す＋動きを止める | 25〜34 fps | 2〜3 | 30〜32 fps |

→ 効くのは影だけ。案1で**アップ中のなめらかさが約2倍、引っかかりはほぼ0**。他を足しても伸びない。

## 案
**案1（おすすめ）：寄っている間だけ、キャラの影を軽くする**（CSS 2行）
- 寄られている人：店の灯りの輪郭（金の縁取り）は残し、壁に落ちる 9px のぼかし影だけ外す。
- 暗くぼかされている他の席：影を外す（もともと暗く・ぼけているので見た目はほぼ変わらない）。
- 引いた画面（いつもの卓）は今のまま。かっこいい見た目は変わらない（前と後の画像を参照）。
- テルの出る確率・見え方・ジンのクセは触らない（見た目の CSS だけ）。

```css
/* テルのアップを軽く：寄っている間は、ぼかし影を外す（輪郭の光は残す）。暗くした席は影なし */
.t3d.focusing .bust .body svg{filter:drop-shadow(1.4px -1.2px 0 color-mix(in srgb,var(--lamp,#e2b65b) 75%,transparent)) drop-shadow(-1px -.5px 0 rgba(255,255,255,.14))}
.t3d.focusing .bust:not(.turn) .body svg{filter:none}
```
入れる場所: `src/01_style.css` のカメラ演出のところ（`.t3d.focusing::before` の行の前後）。

**案2（足すなら）：重い端末だけ、さらに軽くする**
最初のアップで1コマが続けて遅かったら、自動で「周りのぼかし・キャラの揺れ」も止める。案1でほぼ足りるので、実機で重さが残ったときだけ。

**案3：設定で選ぶ**
カメラの設定に「軽い」を足す。案1が効けば不要。

## UI整理（案3）との関係
`research/UI整理と操作性_実装仕様.md` は設定画面の並びを変えるだけで、アップ演出の描き方には触れない。ぶつからない。

## 画面の確認
スマホ縦・横・PC で、寄り・テルのアップの前と後を撮った。重なり・はみ出し・手札やボタンの隠れはなし（CSS の影だけの変更）。

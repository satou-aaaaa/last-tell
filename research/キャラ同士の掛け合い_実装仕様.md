## 0. 変えないもの
- 第1〜3章の難しさ。掛け合いは **CPU の打ち方にも、テルの判定にも、一切つながない**（読むだけの飾り）。
- 第7章（ジンとの一騎打ち）には掛け合いを一つも出さない。ジンは掛け合いの話し手にしない。
- 今の `CHAT`／`QUESTIONS`／`DUEL`／隣の卓の声／観客席／幕間はそのまま。
- お金の話なし。「あの日」。名前に「夜」なし（台詞も「今夜」→「今日」にそろえた）。

## 1. 置き場所
- 今の `BANTER`（20組）を `BANTER_ANY` に置き換える。中身はほぼ同じで、次の2つだけ変えた：
  - ケンジ「負けを取り返すんだよ」→「さっきの続きだよ」
  - ミサキ「このチップ、さっきより減ってない？」／ケンジ「気のせいだって」→ ミサキ「ケンジ、さっきから同じ顔してる」／ケンジ「気のせいだって」
  - 「今夜」3か所 →「今日」
- `BANTER_REACT`、`BANTER_PROG`、`BANTER_ASK` を足す。データ形は台詞.js の頭のコメントのとおり。

## 2. いつ出すか（今の `startBanter` を広げる）
今はハンドの頭に 35% で1組。これを次の順で1つだけ選ぶ形にする。

1. **案2 反応**：直前のハンドでフラグが立っていれば、70% でそれを出す。
2. **案4 巻き込み**：第4章以上（ストーリー）かフリー対戦で、その卓でまだ出していなければ、6ハンド目以降に 15%。1卓1回。
3. **案3 物語**：候補があれば 40% でそちらを優先。
4. **案1 ふだん**：残り。全体の出る割合は今と同じ 35%。

共通の決まり：
- 話し手が全員、卓に座っていて飛んでいないときだけ候補にする（`bust` の本人だけは飛んでいても話してよい）。
- **2ハンド続けては出さない**（出たら次のハンドは休み。反応だけは例外で、休みでも出してよい）。
- 第7章、回想（flashback）、勝負の最後のハンド（`S.finalHand`）、チュートリアル中は出さない。
- `nvBlocked()` と同じく、カットインやクイズが出ているあいだは待つ（今の掛け合いと同じ）。
- 話す間隔は今と同じ 1行 1500ms × `SPEED()`。3〜4行の組もそのまま。

## 3. 単調にしない仕組み（satou さんの依頼の中心）
- **既読の記録** `shisho-banter`：`{v:1, seen:{id:回数}, side:{askId:0|1|2}}`。`SAVE_KEYS` に足して、引き継ぎコード・書き出しに含める。
- 案1・案2の選び方：候補の中で **`seen` が一番少ないもの** から無作為に選ぶ（全部見たら、また少ない順）。案2は `BANTER_REACT` に id が無いので、`'r-'+きっかけ+'-'+番号` を id にする。
- **1卓のあいだ、同じ組は1回まで**。同じきっかけ（案2）は1卓で2回まで。
- **同じ人が続けて話し手にならない**：前の掛け合いの最初の話し手と、次の最初の話し手は別の人にする（候補が残る限り）。
- 案3は、同じ `key` の中で条件に合うもの（`need`/`until`）だけを候補にする。章が進むと自然に入れ替わる。
- 案4の `mem`：一度答えた組の二人が、のちに同じ卓にそろったら、ハンドの合間に1回だけ、選んだ側の一言（`mem[0]` か `mem[1]`）を出す。黙った人には出さない。

## 4. 案2 のきっかけ（見えたことだけで判定）
`endHand()` の中で、次のハンドの頭に使うフラグ `S.bReact={k, s:名前}` を立てる。複数当てはまったら上から優先。

| k | 条件 | 本人 `s` |
|---|---|---|
| `slow` | そのハンドでスロウロールか勝ち誇り（`S.slowrolled>=0` か `taunt(...,'gloat')`）があった | ハヤト／ゴウ |
| `bust` | 主人公以外の誰かのチップが 0 になった | 飛んだ人 |
| `meboss` | 主人公がポットを取り、相手にその章の主役（`CFG.ch.opps[0].name`）がいた（ショーダウンで勝った、または主役が主人公のベットに降りた） | 主役 |
| `suckout` | オールインで両方の手が見えていて、ターン時点で負けていた手がリバーで勝った | 勝った人 |
| `bluff` | ショーダウンで、最後に賭けた CPU の手がワンペア以下だった（`score[0]<=1`） | その CPU |
| `bigpot` | ポットが卓の全チップの4割以上 | 勝った人 |
| `streak` | 同じ CPU が3ハンド続けてポットを取った | その CPU |
| `split` | ポットを分けた | — |
| `mefold` | 主人公がプリフロップで5回続けて降りた（6ハンドに1回まで） | — |

- `sub` がある組は、本人がその名前のときだけ。`sub` なしは誰でも。
- 主人公が降りて見えなかった手は使わない（`SETTINGS.muck` で見せなかった手も使わない）。**相手がこれから何を持つかには、一切ふれない**。
- 反応の掛け合いが出たハンドは、`CHAT_LIARS` などテルの記録に何も足さない。

## 5. 案4 の見た目と動き
- ハンドの合間（`S.handOver` のあいだ）に、前置きの行 → 問い（`q`）を話し手の吹き出しで出す。
- 問いが出たら、今の「揺さぶる」ボタンの場所に **3つのボタン**：`o[0]`、`o[1]`、「黙る」。見た目は今の `QUESTIONS`（`openAsk`）のボタンと同じにする。
- 次のハンドを配るまでに選ばなければ「黙る」と同じ扱い。配る操作は止めない（待たせない）。
- 選んだら `r[選んだ番号]` の行を出し、`shisho-banter.side[id]` に保存。
- **勝ち負け、相手の打ち方、テルには一切影響しない**。図鑑の「噂」や「読み宣言」にも記録しない。
- `SETTINGS.talk` が「少なめ」なら案4は出さない。「なし」なら案2〜4を出さない（案1は今の掛け合いと同じで出す）。

## 6. 表示のこまかいところ
- 船の客の台詞は「（英語で）〜」のように頭に言葉を書く。吹き出しはそのまま出す（カタコトにしない）。英語版（`EN_DICT`）では「（英語で）」を外し、その言葉の原文は出さずに意味だけ英語にする。
- タケルの「（メモ）〜」は、今のメモの吹き出しで出す。「（小さく拍手する）」などの動きは、`TK_GEST` と同じく地の文（「タケルが、小さく拍手した」）にする。
- 「（小声で）」「（メモに一行書き足す）」などのかっこ書きは、吹き出しの中にそのまま出してよい。
- 長い行（25字以上）は、スマホ縦でも吹き出しが卓の外にはみ出さないように折り返す。v57 で直した吹き出しの幅の決まりに合わせる。
- 英語版：新しい台詞は全部 `EN_DICT` に足す（英語版の担当の決まりどおり）。間に合わなければ、英語版では案1の新しい台詞を出さず、既存20組だけにしてよい。

## 7. 第二部
`BANTER_PROG` の最後のコメントのとおり、第二部の担当が「タロウとゲン」「ハヤトとハヤトの弟子」「師匠とジン」の組を足す。仕組みはそのまま使える（`need` は第二部の進み具合で判定する形に広げる）。

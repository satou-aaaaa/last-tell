## 0-1. 同じ種でも画面検査の場面が毎回変わる

### 起きていること
- 「main の QA が ❌」の Issue：#114・#117・#124・#127・#131・#135・#139（10-20 03:10Z〜10-22 00:35Z）。PR の CI は全部 ✅ で取り込まれている。
  - 中身を見ると、#114（捨て札の山が 2♣ を隠す）・#117（勝ち負けの帯が札にかかる）・#124（字幕が Q♣ を隠す、PR は「別の配りで通った」）・#139（左の席の札のはみ出し）は、**その回に何が起きたかしだいで出る崩れ**。#127・#135 は WebKit の止まり・実行機の止まり（別の原因）。
- #139 で確かめた：PR #136 と main（v0.98.4）は中身が同じで、場面「フリー6人_ハンドの終わり・PC」は同じ種（seed 1007・配り 32）なのに、
  - PR：2番の席に白髪の男性、ミサキは「ベット 59,000」、自分のチップ 116,000、札は左の端の内側 → ✅
  - main：2番の席に別の人、ミサキは「オールイン 59,000」、自分のチップ 100,000、札が左へずれて画面からはみ出す → ❌
  - 画像：[PR136_同じ種.jpg](改善提案_2026-10-22/PR136_同じ種.jpg)・[main_v0.98.4_同じ種.jpg](改善提案_2026-10-22/main_v0.98.4_同じ種.jpg)
- 手元（Chromium、PC 1280×800）でも同じ場面を同じ種で開き直すと、**3回のうち1回は結果が違った**。CPU を3倍遅くすると（CI の実行機が混んでいるとき）、**3回とも違った**（2ハンド目まで進んだ回もあった）。

### なぜ起きるか
- 検査の部品（`qa/lib/harness.js:14`）は、種を決めると `Math.random` を1本の乱数の列に置き換える。
- ところがゲームの中では、CPU の判断・座る人選び（`freeSeats`）・顔の描き分け（`realAvatar`）と、時間で動く演出（人だかりの声、隣の卓、待ちの動き など）が、**同じ1本の列を取り合って**いる。
- 演出はタイマーで動くので、実行機の速さしだいで「何回目の乱数をだれが使うか」が入れ替わる → 同じ種でも、座る人・CPU の打ち方・終わるハンドが変わる。
- だから、PR では出なかった崩れが main で出る（逆に、PR で崩れを見逃す）。本線は場面ごとに `showBy:1` などで寄せて直してきたが、場面を足すたびに同じことが起きる。

### 直し方（本線、qa/lib/harness.js だけ。ゲームは変えない）
- 種を決めたとき、`Math.random` を**呼んだ場所ごとに別の乱数の列**にする（呼んだ関数とその呼び元の行で見分ける）。演出がいつ何回呼んでも、CPU の判断や座る人の列はずれない。
- 試した書き方：[harness_案.js](改善提案_2026-10-22/harness_案.js)（今の14行目を2行に）。
  ```js
  const S0 = seed, st = new Map(); const h = s => { /* 種＋場所の名前 → 最初の値 */ };
  Math.random = () => { const k = (new Error().stack || '').split('\n').slice(2, 4).map(l => l.replace(/^.*[/]/, '')).join('<');
    let a = st.has(k) ? st.get(k) : h(k); a = a + 0x6D2B79F5 | 0; st.set(k, a); /* 今と同じ混ぜ方 */ };
  ```
- 手元の結果（同じ場面・同じ種）：

  | | ふつうの速さ | CPU 3倍遅い |
  |---|---|---|
  | 今の部品 | 3回中2回が同じ | 3回とも違う |
  | 案の部品 | 4回とも同じ | 3回とも同じ（ふつうの速さとも同じ） |

- 気をつけること：
  - 入れた版では、座る人・打ち方が今と変わるので、画面の「前の版から変わった」が多めに出る（1回だけ）。baseline.json の画面の項目はその版で取り直す。
  - 場所の見分けに行番号を使うので、ゲームのコードの行がずれると、その場所の乱数も変わる（版をまたいだ見た目の比べは、今と同じく「参考」のまま）。関数名だけで見分けると、名前の無い関数どうしが同じ列を使って4回中3回しか同じにならなかったので、行番号つきにした。
  - 勝率の検査（winrate.js）は種を使っていないので変わらない。rules・fuzz・basics など種を使うほかの検査も同じ部品を通るので、入れたあとに CI で一度確かめる。

### 再発防止の仕組み
- **検査（qa/checks/ui.js に1つ足す）**：「同じ種なら同じ場面」— 場面を1つ（フリー6人_ハンドの終わり・PC。毎回変える必要はない）2回撮り、座る人・チップ・何ハンド目か・場札・見せた札を比べる。違えば ❌「同じ種で場面が変わった（検査の乱数が演出に取られている）」。今は、この食い違いを見る検査が無く、main で ❌ が出て初めて気づいていた。
- **検査（同じ所）**：撮り直し（「場面がずれた」「ページが閉じた」）で ✅ になったものは、まとめに「撮り直して通った」と ⚠ で残す（PR で運よく通ったものを見えるようにする）。
- **`dev/決めたこと.md`**：「画面検査の場面は、同じ種なら毎回同じになること。main だけ ❌ が出たら、まず PR の同じ場面の写真と比べ、場面が違えば検査の側（乱数）を直す。場面ごとに寄せる直し（showBy など）だけで終わらせない」を足す。
- **qa/README.md**：種（seed）と配り（deal）の違い、呼んだ場所ごとの乱数の列のことを1段落。
- 見逃した理由：種を入れたときは演出が少なく、1本の列でも毎回同じだった。そのあと人だかり・隣の卓・心の声などタイマーで動く演出が増えて、列の取り合いが起きるようになったが、「同じ種で同じになるか」をだれも測っていなかった。

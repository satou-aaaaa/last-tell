## 0. 守ること
- **第1〜3章では穴を出さない**（`CFG.ch.no<=3` なら必ず無効）。第1〜3章の相手（ゲン・ハル・ロク・セキ・ミナ）の穴は、フリー・一夜・裏の卓でだけ出る。
- **ジンには穴を持たせない**。第7章の `release` テルと最後のハンドには触れない。
- **ボタンを増やさない**。突くのはふだんのレイズ・コール・フォールド。
- 台本で動く場面（`S.scriptAI`、第5章のAAバッドビート、第7章の最後のハンド `S.finalHand`）では穴を使わない。
- 穴は「性格の数値」より先に判定し、**その場面だけ**行動を上書きする。場面に当たらなければ、今の `cpuDecide()` のまま。
- 相手が主人公を読む仕組み（`selfAdj`、「相手が主人公のテルを見抜く」スレッド）とは別物。混ぜない。

## 2. 判定（`cpuDecide()` の頭、`st` を決めたあと・勝率を出したあと）
`toCall / pot / rel / eq / odds / st` は今の変数をそのまま使う。当たったら `p.leakHit={k,street:S.street,hand:S.handNo}` を残して return。

| k | 場面 | 上書き |
|---|---|---|
| `riverFold` | リバー、`toCall>=pot*0.5`（賭けの直前のポットの半分以上） | `rel<1.8` なら fold |
| `chase` | フロップ・ターン、フラッシュ4枚かオープンエンドがある、`toCall<=pot` | call（勝率が足りなくても） |
| `fold3b` | プリフロップ、自分がこの通りでレイズ済み（`p.raisedPre`）、さらにレイズされた | `rel<2.0` なら fold |
| `oneShot` | ターン、自分がフロップで賭けてコールされた（`p.cbetFlop`）、`toCall===0` | `rel<st.hi` なら check。賭けられたら `rel<st.mid` で fold |
| `stab` | ターン・リバー、`toCall===0`、相手全員がこの通りでチェック済み | 70%で ポットの1/2 を賭ける（`state:'bluff'` 扱い、手が弱くても） |
| `honestRiver` | リバー、`toCall===0` | ブラフの賭けをしない（`rel<1` なら check）。ターンまではブラフを `st.bluff*1.5` |
| `heroCall` | 主人公の賭けを受けたとき（`S.aggr===0&&toCall>0`） | `st.margin-=0.08`、`st.defPost=0` にして今の判定へ流す（return しない） |
| `bigPot` | リバー、`pot>=p.start*0.6` | `eq>=odds-0.08` なら call（少しだけ降りにくい。第6章が簡単になりすぎないよう幅は小さく） |
| `afterLoss` | 直前のハンドで `BB*10` 以上負けた（`p.lastLoss`）、そのハンドのプリフロップ | `rel>0.7` で参加、`r<.35` でレイズ |
| `fitFold` | フロップ、`isWeak(p.hand,S.board)` かつドローなし、`toCall>0` | fold |
| `pairStick` | フロップ以降、ワンペア以上 | `toCall<=pot*1.2` なら call |
| `upTight` | `p.chips>=p.start*1.5` | `st.defPre=1.2` 相当で降りやすくする（return しない） |
| `shortTight` | `p.chips<=p.start*0.5`、プリフロップ | `rel<1.5` なら参加しない（`toCall<=0` なら check） |

ドロー判定は新しく `drawOf(hand,board)` を作る（同じスートが4枚／連続4枚で両側が空いている）。リバーでは false。

準備で足すもの
- `act()` でレイズしたとき：プリフロップなら `p.raisedPre=true`、フロップの最初の賭けなら `p.cbetFlop=true`。`startHand()` で消す。
- `endHand()` で各CPUの `p.lastLoss=p.total-p.won`（そのハンドの負け額）。

## 3. 相手メモの「打ち方」欄
- 保存キー `shisho-leaks`：`{v:1, <name>:{<k>:{seen:n, hit:n}}}`。読み込みは `loadNotes()` と同じく形を確かめ、壊れていたら捨てる。
- **見える場面だけ**記録する（プレイヤーが知りえないことは書かない）。
  - fold で終わった穴（`riverFold` `fold3b` `fitFold` `shortTight`）：その場で記録。
  - call・賭けの穴（`chase` `pairStick` `bigPot` `heroCall` `stab` `honestRiver`）：ショーダウンで手が見えたときだけ記録。
  - `oneShot`：ターンでチェックしたとき記録。`afterLoss`：負けた次のハンドで参加したとき記録。
- `renderNotes()` に「打ち方」の行を足す。テルの行より下、ジンの見立てより下。
  - 例：「セキ：リバーで大きく賭けられて降りた（3回）」「ゲン：大きい賭けにコールして、ドローを外していた（2回）」
  - 文言表 `LEAK_NOTE={riverFold:'リバーで大きく賭けられて降りた',chase:'大きい賭けにコールして、ドローを追っていた',fold3b:'レイズし返されて降りた',oneShot:'フロップで賭けたあと、ターンで止まった',stab:'チェックされたら、弱い手でも賭けた',honestRiver:'リバーで賭けたときは、本物だった',heroCall:'あなたの賭けに、弱い手でついてきた',bigPot:'大きなポットで、最後まで降りなかった',afterLoss:'負けたすぐあとのハンドに参加した',fitFold:'フロップで外れて、すぐ降りた',pairStick:'ペアのまま、最後までついてきた',upTight:'勝っているあいだ、降りることが増えた',shortTight:'チップが減って、参加しなくなった'}`
  - `honestRiver` は「リバーで賭けて本物だった」を数える（ショーダウンで強い手を見せたとき）。
- メモが長くなるので、1人につき回数の多い1行だけ出す。

## 4. ジンの見立て
- `jinView()` の各行のあとに `LEAKS[name].view` を足す（`leakOn` が有効な相手だけ）。例「セキはすぐ降りる。……最後に弱い」。
- いまは第5・6章とフリーなどでしか呼ばれないので、**第4章でも10ハンド目に呼ぶ**（第4章は穴の一言だけ）。
- 答え（どう突くか）は言わない。

## 5. 突いた手ごたえ
- プレイヤーが、穴が出たハンドでポットを取ったら `S.leakWin[name]=(…||0)+1`（記録できた穴だけ。プレイヤーに見えない穴では数えない）。
  - `riverFold` `fold3b` `fitFold` `oneShot` は、相手が降りてプレイヤーが取ったとき。
  - `chase` `pairStick` `heroCall` `bigPot` は、ショーダウンでプレイヤーが勝ったとき。
  - `honestRiver` `upTight` `shortTight` `stab` `afterLoss` は、手ごたえの数には入れない（メモだけ）。
- 同じ相手で2回目：`jinNote('……見つけたな。それが穴だ',1)`、称号 `{id:'leak',name:'穴を突く',hint:'相手の打ち方の穴を、2回突いて勝つ',jin:'……見つけたな。それが穴だ。'}`。
- 今夜の三行（`reviewLines`）に候補を1つ足す：`st.leakWins>=2` なら「相手の穴を、よく見ていたな」。

## 6. 強さの調整
- 第4〜6章が少しやさしくなるので、自動対戦（各章200卓）で勝率を今と比べる。上がりすぎたら穴の条件を狭める（例：`riverFold` の `rel<1.8` を `1.6` へ、`bigPot` の `-0.08` を `-0.05` へ）。
- 目安：第4〜6章の勝率の上がり幅は +5ポイント以内。第1〜3章は**変化なし**（同じ乱数で前後を比べる）。
- 裏の卓の段位（`URA_LV`）とは独立。7段以上（ジンのヒントなし）では、ジンの見立ての一言も出さない。

## 4. データ
### 案1 lessonScene（when:'hand'）
発動条件：`CFG.goal.type` が steal / bluff / readcall、目標が前回進んでから 5ハンド以上、前の発動から 3ハンド以上。
- steal：自分がボタン（3人卓では最初に動く）か、後ろの席で自分より前に動く人が全員ブラインドのとき。ブラインドの人全員の2枚を preTier 0 に入れ替える（山から選び、元の2枚は山の底へ）。
- bluff：自分が最後に動ける席のとき。山を最大300回並べ直し、「相手全員が preTier 0」かつ「フロップで相手の誰もペア以上・4枚のフラッシュ・4枚のストレートが無い」並びを使う。見つからなければ何もしない。
- readcall：相手の1人（第4章はレイカ以外でもよい）に preTier 0、自分に「フロップで2番目か3番目のペア」になる並びを、同じく最大300回で探す。相手のブラフ（39_tell_win.js）とテルはそのまま。
- 第二部第2章（steal n2）にも同じ。第6・7章・第14・15章には入れない。

### 8-1. 型（パターン）を何通りにも見せる
決まった札は「型」として持ち、配るたびに次の4つをばらす。ばらした後に役の強さと勝ち負けを評価関数（bestN・cmp）で確かめ、元の型と違えば、その変え方は使わず次を試す（最大50回、だめなら元の型のまま）。
1. **スート**：4つのスートの入れ替え（24通り）。同じスートどうしの関係（フラッシュ・スーテッド）は保つ。
2. **数字**：型ごとに「数字の幅」を持たせる。例：第5章の1手は「自分にオーバーペア（AA・KK・QQ）、ハヤトにスーテッドコネクター（98s・87s・T9s）、場札でハヤトのフラッシュ」。第7章の最後は「自分にトップペア、ジンにセット」。数字の候補は research/配り札固定_データ.js に足し、組み立ての前に全部の組み合わせを評価関数で確かめておく（qa/unit に検査を足す）。
3. **フロップの3枚の並び**：配る順を入れ替える（6通り）。
4. **席と順番**：一騎打ち・最後の1手が何ハンド目に来るかを、今の決まった数（第7章は5ハンド目から）から幅を持たせる（例：4〜7ハンド目）。席は今の割り当てのまま（決まった席で座るため）。
- 型の数：第4・5章の一騎打ち・第7章の最後は今の3型をそれぞれ5型以上に。第5章の AA と第二部の2場面は1型→3型以上に。
- 案1・案C の場面は、もともと「条件に合う配りを山から選ぶ」ので毎回ちがう札になる。そのうえで、直近3回と同じ2枚（数字とスートが同じ）を自分に配らない。

### 8-2. 遊び直しても同じ型が続かない
- 保存 shisho-story.deal を、型の番号1つから「直近の型の番号を最大3つ」に広げる（{"7":[2,0,4]} の形。古い数字1つの保存はそのまま配列にして読む。loadStory の取り込み許可にも足す）。
- 直近3回に使った型は選ばない（型が4つ以下のときは直近 型の数−1 回）。

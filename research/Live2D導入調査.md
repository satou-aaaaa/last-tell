# Live2D 導入調査（LAST TELL）

調査日：2026-10-08
前提：HTMLで作り、Capacitor で App Store / Google Play に出す。日本の個人開発、広告収入あり。キャラ約8人、表情6種（通常・考え中・強気・困り・勝ち・負け）＋テルのしぐさ（顎の傷を触る など）。

---

## 1. 結論

1. **お金の面は、年間売上1,000万円未満のうちは Live2D 社への契約・支払いは不要。** 広告収入があっても「小規模事業者」扱いで使える。超えたら通知して出版許諾契約を結ぶ（後述）。
2. **技術的にはそのまま載る。** 公式の「Cubism SDK for Web」は WebGL で動くので、Capacitor のアプリ内（iPhone/Android のWebView）でも動く。
3. **一番大きいのは制作費と、絵の作り方が変わること。** Live2D はパーツ分けした専用イラストが必要で、今のコード描画のキャラからは作れない。1キャラあたり数万〜20万円程度、8人で数十万〜100万円超（推測を含む、§4）。
4. **おすすめの進め方：** 師匠（ジン）を1体だけ先に作り、表情とテルが「スマホの画面で読み取れるか」を確かめてから残りを発注する。卓の小さいアイコンは静止画のままにして、Live2D は会話・対面シーンの大きな立ち絵だけに使う。

---

## 2. ライセンスと費用

### 2-1. 「小規模事業者」なら契約不要

Live2D の規約では、**直近の年間売上高が1,000万円未満の個人・事業者**は「一般ユーザー／小規模事業者」で、SDK を使った作品の出版許諾契約と料金が免除される（Live2D Proprietary Software 使用許諾契約 1.21・1.22・2.2項）。

- 「売上高」は**事業全体の売上**で、このゲームの広告収入だけではない。個人事業で他の売上がある場合はそれも合算する（会社員の給与は「事業の売上」ではない、と読むのが自然だが、不安なら Live2D に確認）。
- 他社が実質的に運営している場合は、その会社の売上で判定される（1.25項）。
- 免除は Live2D 社の判断で取り消されることもある、と書かれている。
- **1,000万円を超えたら、原則として翌々月末までに Live2D 社へ通知**する。

### 2-2. 1,000万円を超えたとき（出版許諾契約）

- ゲーム・アプリの広告収入型は「**G 運用型 コンテンツ向けプラン ゲーム/アプリタイプ**」に当たると思われる（公式のフローチャートより。最終判断は Live2D）。
- 料率・金額は公開ページに載っていない。**問い合わせが必要。**
- 契約が必要な場合は、**リリースの1か月前までに申請・締結**が必須。リリース後に超えた場合の手順も問い合わせで確認しておくと安心。
- 「拡張性アプリケーション」（VTuber トラッキングソフトなど）は売上に関係なく審査が要るが、ポーカーゲームは該当しない。

### 2-3. 編集ソフト（Cubism Editor）

自分でモデルを作る場合、または作った後に自分で手直ししたい場合に必要。外注先は自分のソフトで作るので、発注だけなら不要。

| 版 | 価格（税込） | 備考 |
|---|---|---|
| FREE | 無料 | 売上1,000万円未満なら商用OK。ただし制限が厳しい（テクスチャ1枚・2048px、アートメッシュ100、パラメータ30、パーツ30、デフォーマ50 など） |
| PRO for indie（売上1,000万円未満） | 年 ¥15,708（1年目）／月 ¥2,288 | 機能は business 版と同じ。42日間の無料体験あり |
| PRO for business | 年 ¥72,600（1年目）／月 ¥10,582 | |

ゲームのバストアップで「表情6種＋しぐさ数個」なら FREE の制限内に収まる可能性はあるが、手を顔に持っていくテルなどは部品が増えるので PRO 前提で考えたほうが安全（推測）。

### 2-4. 表示義務

- Live2D のロゴやクレジット表記の**義務は規約に見当たらない**。入れるならロゴガイドラインに従う。
- Live2D の名前を作品名に使ったり、公認のように見せるのは禁止。
- Live2D 社は出版された作品を「採用実績」として公開できる。

## 3. 技術：HTML＋Capacitor への組み込み

### 3-1. 使うもの

| 部品 | 内容 | ライセンス |
|---|---|---|
| Cubism Core for Web（`live2dcubismcore.min.js`） | モデルを動かす本体。GitHub にはなく、公式サイトの SDK パッケージに入っている | Live2D Proprietary（再配布は「そのままの形で」アプリに同梱する用途のみ可） |
| Cubism Web Framework | 描画・表情・モーション処理。TypeScript、WebGL。現行は Cubism 5.3 対応 | Live2D Open Software License（GitHub で公開） |
| （代替）pixi-live2d-display | PixiJS 上で手軽に使える非公式ライブラリ | MIT。ただし本家は PixiJS v6・Cubism 4 までで更新が止まり気味。フォーク版が多数あり、長く保守する製品には公式 Framework のほうが安全 |

### 3-2. 組み込みの注意点

- **Core は CDN から読まずにアプリ内に同梱する。** 公式の直リンクは本番非推奨と明記されている例があるうえ、オフライン時に動かなくなる。
- **今の `shisho.html` は1ファイル構成**だが、Live2D はモデル（`.moc3`）、テクスチャ画像、設定 JSON、表情（`.exp3.json`）、モーション（`.motion3.json`）を別ファイルで読む。Capacitor 化の時に「フォルダ構成＋ビルド（Vite など）」に移す必要がある（ゲーム本体は別スレッドの担当なので、ここでは変更していない）。
- **画面に同時に出すのは1〜2体まで**にするとスマホでも軽い。卓の46px アイコンまで Live2D にすると8体同時描画になり、発熱・電池・古い機種での処理落ちが心配。
- **使うキャラだけ読み込み、章が変わったら破棄する。** テクスチャは1体 2048px 1枚程度に抑えるとメモリに優しい。
- **canvas は1枚にまとめる。** WebGL の描画領域は数に上限があるので、キャラごとに canvas を作らない。
- アプリが裏に回った時は描画ループを止める（既存のサウンド停止と同じタイミングで）。WebGL の描画領域が失われた時の再読み込み処理も入れておく。

### 3-3. ゲームとの連携イメージ

| ゲームの出来事 | Live2D 側 |
|---|---|
| 待機中 | 呼吸・まばたき・視線ゆれ（自動） |
| 相手が考えている | 表情「考え中」 |
| 強い手でベット | 表情「強気」＋そのキャラの**テル用モーション**（例：ジンは強い時だけ顎の傷を触らない → 弱い時に触るモーションを再生） |
| オールインされて困る | 表情「困り」 |
| ハンド終了 | 表情「勝ち」「負け」 |
| セリフ表示 | 口パク（音声がないので、文字送りに合わせて口を開閉させる程度で十分） |

- 表情は「パラメータの組み合わせ」なので、ゲーム側は名前（`thinking` など）を指定するだけでよい。
- **テルは「しぐさのモーション」として作り、ゲーム側の既存のテル処理（`CFG.tells`）から呼ぶ。** テルが本物か嘘かのロジックはゲーム側に残し、Live2D は見た目だけを担当させる。

## 4. 制作の進め方と相場

### 4-1. 流れ

1. キャラデザイン（今の方向性：強いキャラはかっこよく、弱いキャラはかわいく）
2. **Live2D 用のパーツ分けイラスト**（目・眉・口・髪・腕などを別レイヤーにした PSD）
3. モデリング（動きの仕込み）
4. 表情・モーション作成
5. ゲームに組み込み、スマホ実機で見え方を確認

2 と 3 は別の人（イラストレーターとモデラー）に頼むことも多い。

### 4-2. 相場（日本の個人クリエイター）

| 項目 | 個人 | 制作会社 |
|---|---|---|
| パーツ分けイラスト | 3〜5万円 | 16〜20万円 |
| モデリング | 1〜5万円 | 20万円〜 |
| モーション1点 | 5千〜1万円 | 5千円〜 |
| 一括依頼 | 5〜15万円 | 30〜40万円 |

（クラウドワークスの記事、2024年5月更新。実績のある人は1体10万円超も普通）

**LAST TELL での概算（推測）：** バストアップ1体＋表情6種＋テル用しぐさ2〜3個で、個人依頼なら1体あたり **約8〜20万円**、8人で **約60〜160万円**。VTuber 用のように「トラッキングで大きく動く」必要はなく、決まった表情としぐさだけなので、VTuber モデルより安く収まる余地はある。

### 4-3. 発注時に決めておくこと

- **キャラ間でパラメータ名をそろえる。** 標準名（`ParamAngleX`、`ParamEyeLOpen`、`ParamMouthOpenY` など）に加え、表情・テル用の独自パラメータの名前を全員共通にすると、ゲーム側のコードが1つで済む。最初の1体で決めて、2体目以降の発注書に入れる。
- **表情・モーションの一覧を渡す。** 表情6種の名前と、キャラごとのテル（例：ジン＝顎の傷を触る）を一覧にする。テルは**スマホの小さい画面でも気づける大きさ**で動かすよう指定する。
- **権利の範囲を契約に書く：** アプリ内での商用利用、広告・ストア画像・PV への利用、改変の可否。
- **元データ（`.cmo3` と PSD）の納品を頼む。** ないと後から表情を足すたびに同じ人に頼むしかない。元データ納品は追加料金になることが多い。
- AI 生成素材の使用可否、クレジット表記の有無。
- 依頼先：ココナラ、SKIMA、nizima（Live2D 公式のマーケット）、X での個人依頼など。ゲーム実績のある人を選ぶと、パラメータ名や書き出し形式の話が早い。

## 5. やる順番（案）

1. 師匠（ジン）1体だけ発注する。表情6種＋顎の傷のテル。
2. 公式 SDK の見本を Capacitor の試作アプリに入れ、iPhone・Android 実機で重さと見え方を確認する。
3. 問題なければ1〜3章のキャラ、その後4〜7章のキャラの順に発注する。
4. 売上が1,000万円に近づいたら、早めに Live2D 社へ問い合わせる。

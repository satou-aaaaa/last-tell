## 案1　ぶれる検査を止める（乱数の固定と回数）　**おすすめ・1.0**
- rules・basics・fuzz でも、勝率と同じように配る札と CPU の迷いの乱数を回ごとに固定する（qa/lib/harness.js の seed をこれらにも渡す）。同じファイルなら何度回しても同じ結果になる。
- コール率など割合を見る検査（S2・A1）は、測る回数を増やし（約30回以上）、少ないときは ⚠️ にとどめる。
- よい点：今日のような「中身は同じなのに ❌」で公開が止まらない。❌ が出たら本当に変わった。
- 弱い点：版をまたいだ比べは、乱数の使い方が変わると並びがずれる（勝率と同じ）。
- 作業：このスレッド。qa/ だけ（ゲームは触らない）。

## 案2　画面を「前の版と並べて」見られるようにし、場面を増やす　**おすすめ・1.0**
- 前の公開版から変わった画面ごとに「前｜今｜違う所に色」を1枚にした画像を作る（qa-results の ui/_比べ_*.jpg）。Claude と satou さんは、変わった場面だけをこの1枚で見る。
- 場面を 12 → 20 ほどに：第7章、第二部の章、6人卓の縦、英語の縦・横、会話の選択肢、チップの数え上げ中、ショーダウン、設定のスクロールの下。
- 重なり判定は今のまま。
- よい点：毎回の画面チェック（決めごと）が早く確実になる。見落としが減る。
- 弱い点：撮る時間が少し延びる（ui の組で +2〜3分）。

## 案3　iPhone の Safari（WebKit）でも回す　**おすすめ・1.0**
- ui（画面の撮影と重なり判定）と fuzz の短い版を WebKit でも回す組を足す。Safari だけで起きる崩れ・止まりを公開前に見つける。
- よい点：遊ぶ人の多い iPhone での事故を防げる。
- 弱い点：字体が Linux の WebKit と本物の iPhone で違うので、文字の幅の判定は Chromium より甘めにする。完全に iPhone と同じにはならない（最後は節目で実機を見る）。

## 案4　公開サイトとしての検査（オフライン・ホーム画面・リンク・速さ）　**ストア提出の前**
- 公開する形（pages.yml が出すファイル）で、オフラインでも開けるか、manifest とアイコンがそろっているか、各ページのリンク切れ、Lighthouse の点（PWA・速さ・読みやすさ）を測る。前の版より下がったら ⚠️。
- よい点：テスト公開・ストア提出の前の確認表（release/README.md）の半分が自動になる。
- 弱い点：ゲームの中身の変更では動かないことが多いので、今すぐの効き目は小さい。

## 案5　通しで遊ぶ検査を夜に回す　**1.0 の後**
- まっさらなセーブから、決まった打ち方で第1章→第7章→第二部へ続けて進め、止まらないか・章が解放されるか・保存が続くかを見る。1時間ほどかかるので、毎日夜に main で回し、❌ なら Issue を立てる。
- よい点：節目レビューの「通しで遊ぶ」の機械でできる部分がなくなる。
- 弱い点：負けると進めないので、ボットの打ち方を章ごとに作る手間がかかる。

## 案6　変わった台詞の一覧を CI が作る　**おすすめ・1.0**
- 前の公開版と比べて、足された・変わった・消えた台詞を、話す人・章ごとに並べた summary を作る（英語が無い行、早見表に合わない一人称、お金の話・「夜」も印を付ける）。
- よい点：版ごとのクリエイター目線・交代レビューで、Claude がゲームのファイルを読まずに済む（トークンが一番減る所）。物語が中心のゲームなので効き目が大きい。
- 弱い点：台詞をデータで持っていない古い所は拾い漏れがある（拾えた割合を出す）。

## 案7　守りの基本（前回の案4・5）
- 前半（今）：「検査のまとめ」は PR #22 で毎回動くようになったので、QA を全部の PR で回し、ルールセットで「検査のまとめ ✅ が必須」にする。設定は satou さんの操作（Settings → Rules）。
- 後半（1.0 の後）：外の部品を SHA で固定、package-lock と Playwright 入りの入れ物（コンテナ）で毎回の入れ直しをやめる（各組2〜3分短く）。

## クリエイター目線の3行
- どの柱に効くか：師弟の物語（案6・案5：台詞と通しの流れを毎版確かめる）と、ライブの空気（案2・案3：スマホで崩れない卓）。
- 最初の5分への影響：直接は無い。iPhone での崩れ（案3）と画面の見落とし（案2）を公開前に止めるので、最初の5分で壊れた画面を見せる事故が減る。
- 1.0 か公開後か：案1・2・3・6 と案7前半は 1.0 の前（テスト公開の前に効く）。案4 はストア提出の前、案5・案7後半は公開後。

## 1. 何が変わるか（遊ぶ人から見て）
- 各席の前のチップが、ブラインドに合わせた額（いまは青1,000・赤5,000が中心）で積まれる。100BBで40枚ほどになり、深い人・浅い人がひと目でわかる（案1）。
- 20枚ずつの塔になり、高い額は奥の列、小さい額は手前の列に並ぶ。2〜3枚の端数は横に寝かせてあり、塔は少しずつずれている（案2）。
- 勝ったポットの山が、勝った人の前にごちゃっと残る。強いキャラ（rank3以上）とアオはすぐ塔へ積み直し、弱いキャラは次のハンドまで崩れたまま（案3）。
- 公開後：考え中のCPUがチップをいじる（案4）。オールインのとき、塔をそのまま線の前へ押し出す（案5）。

## 4. データ（そのまま入れられる形）
見本で確かめた割り方（BB=2,000 のとき 100,000→青20＋赤16＝36枚、235,500→黒1＋赤40＋青25＋白1、42,500→赤4＋青22＋白1）。
```js
// 案1：BBの半分のチップを20枚、その5倍を40枚まで。それより上の分だけ大きい額にまとめる
const SB_DENOMS=[100,500,1000,2500,5000,10000,50000,100000];
function stackBreak(amount,bb){bb=bb||BB()||2000;const D=SB_DENOMS,C={};STACK_DENOMS.forEach(([v,c])=>C[v]=c);
  const base=D.filter(v=>v<=bb/2).pop()||100,mid=D.filter(v=>v<=base*5).pop(),hi=D.find(v=>v>mid)||mid;
  const n={};let a=Math.max(0,Math.round(amount)),low=a%base,rest=a-low;
  for(const v of D.filter(v=>v<base).reverse()){const k=Math.floor(low/v);if(k){n[v]=k;low-=k*v}}
  let lp=Math.min(rest,20*base+40*mid);lp=rest-Math.floor((rest-lp)/hi)*hi;let up=rest-lp;
  for(const v of D.filter(v=>v>=hi).reverse()){const k=Math.floor(up/v);if(k){n[v]=k;up-=k*v}}
  const m=Math.min(40,Math.floor((lp-Math.min(lp,20*base))/mid));n[mid]=m;n[base]=(lp-m*mid)/base;
  return STACK_DENOMS.map(([v,c,nm])=>({v,c,nm,n:n[v]||0})).filter(d=>d.n>0)}
```
- 持ち点は100の倍数である前提（いまのゲームはそう）。100未満の端数が出る額があれば、合計が合わなくなるので 7. の検証で見つける。
- 1席の塔が **6本を超える** ときは、`lp` の上限（20*base+40*mid）を半分にしてもう一度割る（大きい額が増え、塔が減る）。それでも超えたら塔の高さは20のまま、本数を6で切る（見た目だけ。拡大表示では全部出す）。

塔の並べ方（見本の `towers(...,'live')` を元にする）：
- 額の高い順に並べ、前半の額を奥の列、残りを手前の列にする。1種類だけなら手前の列だけ。
- 各額は20枚ずつの塔。最後の塔が 1〜2 枚で、その額が4枚以上あるときは、その1〜2枚を寝かせて手前に置く（`rotate(-20〜20deg)`、影を薄く）。
- 塔の横位置に ±1px、チップごとに ±0.8px のずれ。乱数は `席番号＋持ち点` から作り、描き直しても形が変わらないようにする（`potRnd` と同じやり方）。
- 1枚の厚み：いまの `step`（3〜4px）のまま。塔は20枚まで。

## 5. 守ること
- 第1〜3章の難しさを変えない／第7章のジンの本物のテルに触れない。表示だけで、`p.chips` や CPU の判断には一切触らない。
- 「夜」を使わない／セリフにお金の話を入れない（この仕様に台詞は無い）。
- 顔にかからない：チップは卓の上だけ。`.mystack` の上端が、その席の札（`.hand .card`）の上端より上に出ない。
- 数えたら合う：表示する枚数×額＝持ち点（塔を6本で切ったときの小さい表示を除く）。タップで数える機能・ディーラーが数える・「約〜」表示はそのまま。
- 6人卓のスマホ縦（幅420以下）は今は `.mystack` を消している。塔を **最大3本・scale(.6)** で出してみて、札・名札・賭けチップと重なるなら今のまま消す（画面で決めてよい）。
- 案3：崩れた山は次のハンドの最初（配る前）に必ず塔へ戻す。崩れたままのチップも持ち点に数える（`p.chips` は配当の時点で増えている）。
- 案4（公開後）：見た目だけ。テルの札（`#cue`）や `p.tell` とつながない。第7章のジン、回想（flash）、第6章のクロウの逆テルの最中には出さない。`prefers-reduced-motion` で止める。
- 案5（公開後）：オールインの賭け額は今の `.chipwrap`（賭けチップ）にも出ているので、塔を押し出すときは `.chipwrap` を隠し、塔だけを前へ動かす（両替しない）。名札に赤い枠。`reducedMotion()` では動かさず、位置だけ前にする。

## 6. 案3の動き
- `potPush` で、勝った人ごとの山（`groups[gi]`）を、名札ではなくその人の `.mystack` の **手前（卓の中央側）約14px** の位置へ飛ばす。いまの `scale(.55)`→`opacity:.1` で消すのをやめ、着いたら `opacity:1` のまま、チップを1枚ずつ `rotate(±25deg)` にばらして残す。
- 置き場所：席ごとの `.mystack` の中に `<span class="won-pile">` を作り、そこへ移す（再描画で消えないよう、`render()` は `won-pile` を残して塔だけ描き直す）。
- 強いキャラ（`rankOf(p.name)>=3`）とアオ：着いてから 900ms 後に、山のチップを塔の上へ吸い込ませ（`.45s`、1枚ずつ 30ms ずらす）、塔を新しい持ち点で描き直す。
- 弱いキャラ：次のハンドの配りが始まるときに同じ動きで積み直す。
- 引き分け（山を交互に分ける）は今の分け方のまま、それぞれの前に残す。
- `reducedMotion()` のときは飛ばさず、すぐ塔を描き直す。

## 7. 「できた」の条件（自動検証に足せる形）
- BB=2,000 で持ち点 100,000 の席の `.mystack .chip` が 30〜45 枚ある。

- `.mystack` の塔（`.col`）は1本あたり20枚以下、1席6本以下。
- スマホ縦・横・PC で、`.mystack` が名札（`.plate`）・顔（`.bust .body`）・札（`.hand .card`）と重ならない（qa/checks/ui.js の重なり判定に `.mystack` を足す）。
- 第1〜3章の勝率（qa/checks/winrate.js）が今と変わらない。
- 案3：配当のあと次のハンドの最初に、どの席にも `.won-pile` の中身が残っていない。
- 案4：第7章で手癖のアニメーションが1回も出ない。
- 目で見る：塔が奥と手前に並び、きれいすぎず、ライブの卓に見える（見本と見比べる）。
- 目で見る：勝ったあと、強いキャラはすぐ積み直し、弱いキャラは崩れたまま。

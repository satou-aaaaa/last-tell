### poses.json の形
```
{ "表情名": {
    "bones":    { "FACIAL_C_Jaw": [[dx,dy,dz], [qx,qy,qz,qw]], ... },   // 動く骨だけ（約 250〜800 本）
    "shapes":   { "jaw_open": 0.42, "McornerPull_Jopen_L": 0.3, ... },   // blend shape の重み（FBX の名前の「__」より後ろ）
    "maps":     { "head_cm3_color.head_wm3_smile_L": 1.0, ... },         // しわの絵のマスクの重み（参考。いまは未使用）
    "controls": { "CTRL_expressions.jawOpen": 0.42, ... } } }            // 動かした操作（参考）
```
当て方（Skeleton3D の骨ローカル。dx… は m）：
```
pose_position = rest.origin + Vector3(dx,dy,dz)
pose_rotation = rest.basis.get_rotation_quaternion() * Quaternion(qx,qy,qz,qw)
```
載っていない骨は rest のまま。重ねる（mood ＋ 目線 ＋ 口パク）ときは、位置の差を足し、回転の差を順に右から掛ける。重み w は位置 ×w・回転は `Quaternion.IDENTITY.slerp(q, w)`。

## 何を読んだか（一次資料）
- **OpenRigLogic**（Epic Games, MIT, https://github.com/EpicGames/OpenRigLogic ）。`5.8` ブランチ（commit 55756ac, 2026-09-30）。DNA を読み書きする `dna` と、UE と同じ評価をする `riglogic` の C++ と Python 版。README に「UE の DNA を UE と同じ実行時の評価で動かせる」とある。**DevKit や Fab の素材は不要**（Fab の「OpenRigLogic Sample Content」は使っていない）
  - 設計の文書（gh-pages-source ブランチ `docs/design/design.md`）：計算は 3 段 ①PSD（組み合わせの入力＝入力の積、上限つき）②線形（ジョイントグループごとの密な小行列 × 入力。LOD は行を減らすだけ）③条件つき（区間ごとの傾き・切片。主にしわのマスク）。出力は「骨の変化・blend shape の重み・しわのマスク」で、どれも**休みの姿勢からの差**
  - `src/riglogic/joints/JointsFactory.cpp`：休みの値（neutral）は出力とは別に持つ＝`getJointOutputs()` は差
  - `include/tdm/Quat.h`：オイラー角 xyz → 四元数の式（Maya の xyz＝X を先に回す、行列は Rz·Ry·Rx）
- **MetaHuman-DNA-Calibration**（https://github.com/EpicGames/MetaHuman-DNA-Calibration 、最後は 1.3.1／2024-12）の `dna_viewer/builder/joint.py`：Maya で骨を作るとき DNA の休みの回転を **jointOrient** に入れる（RigLogic の出力は rotate に入る）。→ 回転の合成は「休み × 差」
- **Character DNA アドオン（Poly Hammer, 旧 meta-human-dna）**：中は OpenRigLogic を使っている（README）。骨へ当てる所は配布の native モジュールで、ソースには無い。入れるのにアカウントが要るので使っていない。参考のみ
- 「古い dnacalib は 5.6 以降の DNA を読めない」の件：**OpenRigLogic 5.8 の dna は今回の head.dna（UE 5.8.4 の DCC 書き出し、形式 gen 2 / v5）を問題なく読めた**。古い dnacalib は試していない（不要になった）

## head.dna の中身（Jin＝Walter）
- 名前 Archetype / DB MH.6、LOD 8、骨 870（うち FACIAL_* 843、ほかは spine_04〜head と肩）、raw control 263（`CTRL_expressions.*` 251 ＋ 首・頭の四元数 12）、GUI control 174、PSD 545、blend shape の通り道 782、しわのマスク 82、RBF 1（首まわり）、ニューラルネット 0
- 座標：x＝キャラの左、y＝上、z＝前（右手系）、cm、度、xyz 順
- LOD ごとの骨：LOD0 840 / 1 617 / 2 413 / 3 301 …。**LOD2 の骨の値は LOD0 と同じ**（RigLogic の LOD は行を減らすだけ。確かめた）→ 一つの poses.json が LOD0 と LOD2 の顔に使える。blend shape は LOD0 だけ

## どう計算したか
1. OpenRigLogic を自分で組み立てた（cmake ＋ SWIG。SWIG 4.5 は包みでこけるので 4.2.1）
2. raw control を全部 0、首・頭の四元数を (0,0,0,1)（RBF が休みを出すように）、表情の操作だけ値を入れて `RigLogic.calculate` → 骨ごと 9 値（位置の差 cm, 回転の差 度, 大きさの差＝今回は全部 0）、blend shape の重み、しわのマスク
3. 単位を m に、回転の差を xyz 順で四元数に
4. **軸の変換**：Godot に取り込んだ Skeleton3D の休みの姿勢（全 875 本）を書き出して DNA と比べた。骨の空間は「DNA を x 軸まわりに +90° 回したもの（Z 上。親の Node が Y 上に直している）」で、**各骨のローカルの軸は DNA と全く同じ**（870 本で位置 1e-6m、向き 1e-5 以内）。だからローカルの差は単位を変えるだけでそのまま使え、UE→Godot の軸の入れ替えは要らない（UE の左手系への変換は FBX の書き出し・取り込みの中で打ち消されている）
5. 回転の合成「休み × 差」と「差 × 休み」の両方で左右の対称を調べたが差はごくわずか（顔の骨は休みの回転が単純）。Maya の jointOrient の決まりに合わせて「休み × 差」に
6. 確かめ：eyeLookLeft で目が画面の右（キャラの左）、eyeLookUp で上、jawOpen であごが 22.6° 下がる、まばたきで両目が閉じる、を画像で確認

## 分かったこと・残る問題
1. **blend shape はほぼ要らない**：表情で使う形の動きは最大 4mm（talk_2 の jaw_open）、組み合わせの補正（大文字始まり）は最大 0.3mm。→ **追記（下の「続き」）で全部外した**
2. **あごの黒いしみ** → **追記（下の「続き」）で原因（FBX の接線）を突き止めて直した**
3. **重ね方・重みは近似**：RigLogic の骨は「入力＋PSD（入力の積）」に線形なので、表情を 0.5 倍したものは、操作を 0.5 にしたものと少し違う（PSD が積のため）。見た目では気にならない。厳密にしたいなら途中の値（例 talk の各こま）も焼いておく
4. **首・頭の向き**は入れていない（体の骨。首の補正の RBF は休みのまま）。lose で頭を下げる、think で首をかしげる、などは別に体の骨で
5. **しわの絵**（CM/WM）：`maps` に重みは出しているが、Godot の材質はまだ使っていない（UE ではマスクで混ぜる。shader が要る）
6. 口パクは 4 こまだけ。声に合わせるなら、音の大きさで mouth_open の重みを動かす＋たまに talk_3 くらいが手軽
7. 表情の値は白人の年配の仮の顔で決めた。**日本人 6 人の DNA は同じ骨の並び（MH.6）なので、道具はそのまま使えるはず**。顔が違うので、見て値を少し直す前提（`--expr` で上書きできる）
8. 毎こまの当て方：GDScript で 875 本を戻して当て直すのに 1 表情 約 1ms、3 つ重ねて約 2ms（この機械）。卓の 5 人を毎こま動かすなら、骨の番号を先に引いて配列で持つなどの工夫を
9. 実時間の RigLogic（GDExtension）は今は要らない。焼いた姿勢で mood・cue・目線・口パクは足りる。顔の演技を細かく（MetaHuman Animator の録画など）入れたくなったら、OpenRigLogic を GDExtension にする道がある（MIT なので可）

### 1. 骨だけで動かす（blend shape を全部外した）
`import_prune.gd` に `KEEP_BLEND_SHAPES := false`（true で前のふるまいに戻る）。頭の LOD0/LOD2 の 858 本を全部外す。表情は poses.json の骨だけで出る（`expr_moods.png` など、全部この状態で撮り直した）。poses.json の `shapes` はそのまま出している（使わなくてよい）。

| | 前（基本の形 294 本を残す） | 後（形なし） |
|---|---|---|
| 頭の .scn | 194 MB | **2.2 MB** |
| GPU のバッファ（buf_mem） | 211 MB | **15 MB** |
| GPU 全体（video_mem） | 258 MB | **72 MB** |
| まっさらな取り込み（全部） | 3分54秒 | 3分31秒〜3分44秒 |

- 取り込みの時間はほとんど縮まない（ufbx が FBX の 858 本を読むところが重い。Godot の FBX 取り込みに「blend shape を読まない」設定は無い）。縮めたいなら FBX を書き出すときに形を外す（UE 側）か、取り込んだ結果（.scn/.res）を置いて FBX を置かない
- 1 こまの重さは、この機械で別の担当の Godot が同時に動いていて（load 4〜5）比べられなかった。三角形・描画呼び出しは同じ。形の計算が無くなるぶん軽くなる方向
- 絵の VRAM は 47→57MB（法線マップを「法線マップとして」圧縮したため。下の 2）

### 2. あご・頬の黒いまだら：原因は FBX の接線。作り直して直した
調べた順（`expr/fix_blotch_tests.png`）：
- blend shape を 0.001 だけ効かせる → 消えない。1.0 で効かせると消える。Godot の blend shape は「正規化」なので重み 1 だと接線が形の側の接線に置き換わる → **基本のメッシュの接線**が怪しい
- 法線マップを外す → まだらがほぼ消える（法線マップ × 接線の問題。肌の色の絵にはしみは無い）
- 頭の LOD0 の接線を書き出して UV の向きと比べた：**接線と UV の U 方向の一致（cos）の平均 0.15、符号（w）は 7 割が＋・3 割が−とばらばら**。FBX（UE の書き出し）から来る接線が UV とそろっていない。mikktspace（Godot の SurfaceTool.generate_tangents）で作り直すと cos 0.999、符号も全部そろう
- 法線マップの緑の向き：絵から測った（赤の横の変化と緑の縦の変化の相関）。Head/Body/Teeth/WM1-3 は **DirectX 式（緑が下向き、相関 −0.2）→ これまでどおり `normal_map_invert_y=true` が正しい**。Eyes は OpenGL 式（+0.28）なので反転しない
- 接線を作り直し＋反転あり、が自然（しわが溝に見える）。接線を作り直し＋反転なし、はしわが盛り上がって見える（`5_mikk_no_invertY`）
- 直したこと：`import_prune.gd` で頭（と体）のすべての面の接線を作り直す。法線マップの .import を `compress/normal_map=1`（「Detect」のままだと材質を実行時に作るので色の絵として DXT1 で圧縮されていた）
- 結果：`expr/fix_blotch_before_after.png`（左が前、右が後）。**blend shape を外しても、どの表情でもまだらは出ない**。体（`bust_after_fix.png`）の腕のしわは A ポーズで脇に寄った皮膚のしわの絵で、まだらではない

### 3. しわの絵（WM/CM）を表情に合わせて混ぜる shader（試した。効果はある。使うかは場面しだい）
- しくみ：DNA の animated maps の出力（`maps`、例 `head_wm3_normal.head_wm3_smile_L`）の重み × Masks/ のマスク（10 枚 × RGBA）を、**dna_poses.py が表情ごとに 1 枚の「しわの量の絵」（256×256、R=WM1, G=WM2, B=WM3）に焼く**（`--masks <Masks フォルダ>` → `wrinkle/<表情>.png`、poses.json の各表情に `"wrinkle": "<表情>.png"`）。shader（`jin_walter/head_skin_wrinkle.gdshader`）は、量の絵 2 枚（重ねる用）を見て、基本の法線・色と WM1-3・CM1-3 を混ぜる。テクスチャは 11 枚（Compatibility の 16 枚の上限に収まる）
- マスクのチャンネルの割り当ては、マスクの絵を目で見て決めた（例 wm1_msk_02 は R/G＝まばたき左/右、B/A＝目頭の squint 左/右。左右は UV で「キャラの左＝絵の右」）。cheekRaise の Inner/Outer/Upper の 3 つは区別があいまい（同時に動くので見た目には影響しない）。正確な表は UE の頭の材質（M_Head の MaterialFunction）を見れば分かる
- 見え方（`expr/wrinkle_off_on.png`、左＝なし／右＝あり）：**fast・lose（額の横じわ）と win（目尻・頬）ではっきり差が出る**。worried・stare・sweat は弱い。CM（色）の差はごく小さい（平均 0.4%）
- 重さ：VRAM +24MB（2048² の絵 6 枚）。この機械（CPU 描画、別の担当と同時）では顔のアップの 1 こまが約 1.5 倍に。本物の GPU なら 6 回のテクスチャ読みは小さいが、5 人並べるなら**顔のアップだけで使う**か、CM を外して WM だけ（3 枚）にするのがよい
- 使い方（試験シーン）：`wrinkle=1`（`wgain=1.5` で強める、`wcolor=0` で色なし）。`apply_expr` が表情の量の絵を材質に渡す
- 判断：**効果はあるので残す（オプション）**。標準の材質はこれまでどおり StandardMaterial3D

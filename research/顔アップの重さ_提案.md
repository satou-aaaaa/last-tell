# 相手が打つたびの「顔のアップ」が重い件（2026-10-11 提案）

satou さん：「プレイヤーがアクションするときに顔にアップするせいで、表示が重くなっているように見えます」

## 結論
- 原因は2つ。どちらも、これまでの対策（テルのアップの影 案1、動作の重さ 案1〜4）では手を付けていない所。
  1. **寄るたびに、卓・チップ・相手5人をぼかして暗くするフィルター**。寄る・戻るたびに、拡大した大きさで描き直しになる。番が回るごとに寄る（20秒で11〜14回）ので、そのたびに起きる。
  2. **吹き出しの追いかけ（sayFollow）が、吹き出しが出ている約3秒のあいだ毎コマ動く**。カメラが止まっていても測り直している。実戦で全体の処理時間の約1割。
- おすすめは **案A＋案C**（普段の番は寄らない＋吹き出しの追いかけを動く間だけに）。テルのアップ・大きな賭けの前のにらみ・帯と文字はそのまま。

## 測り方
- テストサイトと同じ v0.71 系（src の今の版で組み立て）。スマホ縦 390×844・DPR3・CPU 4倍遅く。
- ①決まった流れ：相手5人に順に番を回す×2周（寄る→吹き出し→次の人）。②実戦：フリー6人・普通の速さ・自分は自動でコール、20秒。
- 道具は `research/顔アップの重さ/`（下の「ファイル」）。
- 注意：この検査用ブラウザには GPU が無く、画面の合成を CPU でやるため、コマ数（fps）はどの案でもほぼ同じ（26〜35）に張り付いて差が出なかった。そこで「描き直しの量（RasterTask の合計時間）」と「処理の時間」で比べた。実機の体感の差は、satou さんのスマホで確かめるのが確実（下の「すぐできる確認」）。

## 測った結果
①決まった流れ（12.6秒、3〜6回の中央値）
| | 描き直し | 遅いコマ（50ms超） |
|---|---|---|
| 今 | 6.4秒 | 30 |
| カメラ演出オフ（参考） | 3.4秒 | 34 |
| 寄らない・ぼかさない（＝案A の普段の番） | 2.4〜4.4秒 | 22〜41 |
| 寄るが、ぼかしと暗くするのをやめる | 4.7〜5.3秒 | 22〜41 |

| will-change・切り替えを瞬時に | 5.8秒前後 | 30〜35（効かない） |

- 寄ることとフィルターの両方で、描き直しがカメラオフの約2倍になる。暗くする（brightness）も、ぼかし（blur）と同じくらい重い。寄る大きさを小さくしても半分ほどしか減らない。

②実戦（20秒）
- 寄った回数：今 11〜14回 → 案A 2〜9回（テルが出た番の数で変わる）。
- 吹き出しの追いかけの時間：今 1.7〜2.3秒 → 案C 1.0〜1.5秒 → 案A＋C 0.7〜1.1秒。今はカメラが全体のままでも動いている（案A だけだと、全体の間に 129〜152回 空回りする）。
- 位置合わせ（lpFrame）全体では 20秒のうち 3.6〜4.7秒。その約半分が吹き出しの追いかけ。

ついでに見つけたこと：寄っている間、卓にかかるぼかしが **自分のチップの数字と自分の顔の枠** にもかかっていた（前と後の画像の左下）。案A・案B どちらでも直る。

## 案
### 案A ◎ 普段の番は寄らない（1.0）
- チェック・コール・フォールドなど、テルも大きな賭けもない番は全体のまま（名札の光で番が分かる）。寄るのは「テルが出た番」と「大きな賭けの前にじっと見る番」だけ。テルへの寄り直し・レイズとオールインの帯と文字は今のまま。
- 寄るたびの描き直しとフィルターが、普段の番では丸ごと無くなる。寄る回数は 1/2〜1/5。
- 寄る時の意味がはっきりする（寄った＝何かある）。ライブ感の方針（テレビの演出を減らす）にも合う。
- 第1〜3章の難しさ・テルの出る率は変わらない（見せ方だけ）。
- 中身：`24_dokidoki_camera.js` の camUpdate に1行と、判定の関数1つ（`research/顔アップの重さ/cam_calm.js`）。
- 気になる点：カメラ演出 案2（2026-10-09 決定）の「CPUの番で寄る」を変える。

### 案B ○ 寄るのは残し、ぼかし＋暗くするのをやめる（1.0）
- ほかの人は半透明で沈め、卓には暗い幕を1枚。ぼかしは無くなる。描き直し −20〜30%。
- 見た目：ピントがずれた感じが無くなる。半透明にすると首と胴のつなぎ目が少し透ける（画像 `案B_前と後_*.png`）。
- 中身：CSS 5行（`research/顔アップの重さ/案B_ぼかしをやめる.css`）。
- 案A と一緒でもよい（テルの寄りの時だけ効く）。

### 案C ◎ 吹き出しの追いかけは、カメラが動いている間だけ（1.0）
- 今は吹き出しが出ている約3秒、毎コマ位置を測り直す。カメラが動いている間（最長0.7秒）と、吹き出しが出た直後（0.3秒）だけにする。
- 見た目は変わらない（止まっている時は吹き出しも動かないため）。追いかけの時間 −35〜60%。
- 中身：`36_layout_pass.js` の sayWake と lpFrame の2行、`24_dokidoki_camera.js` の camTo の1語（下）。

### 案D △ 寄る大きさを小さく（1.5倍→1.15倍）
- 描き直しは約2割しか減らない。顔が見えにくくなる割に効かないので、おすすめしない。

## おすすめ
**案A＋案C を 1.0 に。** 案B は、A＋C のあとでもテルの寄りが重い時に足す。

## すぐできる確認（satou さんのスマホで）
卓の右上の「カメラ」を「オフ」にして、重さが消えるか見てください。消えるなら原因は寄りで、案A がいちばん効きます。オフでも重いなら、原因は寄り以外（相手が打つたびの描き直し）なので、そちらを調べ直します。

## 本線への渡し方（決まったら）
案A（24_dokidoki_camera.js）
```js
// camUpdate の前に
// 顔アップの重さ 案A（2026-10-11）：寄るのはテルが出た番と、大きな賭けの前にじっと見る番だけ
function camWorth(i){const p=S.players[i];if(!p)return false;const tl=p.tell;return !!(tl&&tl.street===S.street&&!p.folded)||S.stare===i}
// camUpdate の `if(S.camSkip===i){...}` の次の行に
  if(!camWorth(i)){clearTimeout(camBackT);if(camState.kind!=='wide')camTo(-1,'wide');return}
```
案C（36_layout_pass.js と 24_dokidoki_camera.js）
```js
// lpFrame の中
  if(LP.say){let on=false;try{on=sayFollow()}catch(e){}LP.say=on&&performance.now()<LP.until}
// sayWake を置きかえ
LP.until=0;
function sayWake(ms){LP.say=true;LP.until=Math.max(LP.until,performance.now()+(ms||300));lpKick()}
// camTo の頭： sayWake() → sayWake(800)
```
- どちらも scratch で組み立てて、文法の検査は通った（error 0件）。実戦20秒×3回でエラー無し。
- 本線で：`sh qa/run_all.sh`、3つの画面（縦・横・PC）で吹き出しの位置と重なりを確認。テルが出た番だけ寄ること、にらみ（stare）で寄ること、第1〜3章の勝率が変わらないことを確かめる。

## 0-2. 電波の弱い所で開くと、真っ白のまま待たされる

### 起きていること
- テスト公開の `sw.js`（オフライン用のしくみ）は、ゲーム本体を「ネット優先」で読む（48〜60行目）。ネットにつながらないと分かれば、すぐ保存した版を出す（今の検査 site.js「オフライン」はこれを見ていて ✅）。
- ところが**電波はあるのに返事が来ない**とき（地下鉄・エレベーター・混んだ駅の Wi-Fi など、スマホではよくある）は、`fetch` が失敗にならず待ち続ける。そのあいだ画面は真っ白。
- 手元で確かめた：一度開いて保存させたあと、サーバーが index.html に返事をしないようにして開き直すと、**20秒以上たってもタイトルが出ない**（Chromium、390×844）。
- ゲーム本体は gzip で約 560KB あり、遅い回線ではそもそも数秒かかる。

### 直し方（テスト公開のリポジトリの sw.js、本線）
- ページ（navigate）のときだけ、**ネットの返事を4秒まで待ち、来なければ保存した版を出す**。ネットの読み込みは止めずに続け、届いたら保存しておく（次に開いたときは新しい版。今の「新しい版があります」のお知らせ 17b_update.js もそのまま働く）。
- 手元で試した書き方（`fetch(req)` を `Promise.race` で 4秒の保存版と競わせる、6行ほど）で、同じ条件で **4.7秒でタイトルが出た**。
  ```js
  const net = fetch(req);
  const late = new Promise(r => setTimeout(r, 4000)).then(() =>
    caches.match(req, { ignoreSearch: true })
      .then(r => r || (isTop ? caches.match('./index.html') : undefined))
      .then(r => r || net));
  e.respondWith(Promise.race([net, late]).then(res => { /* 今の保存の処理 */ }) ...
  ```
  （保存した版が無い初回は、今と同じくネットを待つ。）

### 再発防止の仕組み
- **検査（qa/checks/site.js に1つ足す）**：「電波が弱いとき」— 一度開いたあと、テスト用のサーバーが index.html だけ返事をしないようにして開き直し、**6秒以内にタイトルが出る**こと。出なければ ❌。今の「オフライン」の検査は、すぐ失敗が返る場合しか見ていなかったのが見逃しの理由。
- **`dev/決めたこと.md`**：「sw.js でネット優先にするものは、待つのは4秒まで。それより遅ければ保存した版を出す」を足す。

- 最初の5分：影響あり（2回目以降に開くとき。外で開く人ほど当たる）
